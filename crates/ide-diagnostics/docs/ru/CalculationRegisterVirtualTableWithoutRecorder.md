# Виртуальная таблица регистра расчёта без отбора по регистратору (CalculationRegisterVirtualTableWithoutRecorder)

## Описание диагностики

Виртуальные таблицы регистра расчёта `ДанныеГрафика`, `ФактическийПериодДействия` и `База<Регистр>` без отбора строятся по всем записям регистра, и для каждой записи платформа вычисляет значения. При расчёте нужны только записи рассчитываемого набора, поэтому в параметре-условии таблицы ставится отбор по регистратору.

Диагностика отмечает обращение, в параметре-условии которого нет отбора по `Регистратор` (`Recorder`). Параметр-условие — первый параметр у `ДанныеГрафика` и `ФактическийПериодДействия` и четвёртый у `База<Регистр>`.

Правило эвристическое: оно не знает, рассчитывается ли в этом месте собственный набор записей. Поэтому уровень по умолчанию — предупреждение. Чтение истории сотрудника по другим документам вполне законно, и отбор по своему регистратору изменил бы результат такого запроса: добавлять его нужно только там, где действительно рассчитывается свой набор.

Отбором считается:

- сравнение `Регистратор = <выражение>` в любую сторону;
- `Регистратор В (<список>)`;
- такое сравнение как часть условия, связанного через `И`, в том числе в скобках.

Срабатывания нет и при явном исключении `Регистратор <> <выражение>` в любую сторону, отдельно или под `И` и в скобках: оно показывает, что записи других документов нужны намеренно.

Отбором не считается: условие в `ГДЕ` запроса, отбор по другому полю, сравнения `<`, `>`, `<=`, `>=`, `НЕ`, `НЕ В`, `В ИЕРАРХИИ`, сравнение только под `ИЛИ` (в том числе `Регистратор = &А ИЛИ Регистратор = &Б`), поле через точку `Регистратор.Номер`.

Если на таблицу уже указывает `VirtualTableCallWithoutParameters`, эта диагностика ей не дублируется: исправление здесь — перенести условия в параметры таблицы, а не добавить регистратор. Сообщение про регистратор не возвращается и тогда, когда `VirtualTableCallWithoutParameters` отключена в настройках. Таблица `База<Регистр>` в `VirtualTableCallWithoutParameters` не проверяется, поэтому без условия в четвёртом параметре она отмечается и при пустых скобках.

Список параметров, который модуль дописывает при выполнении (`"…ДанныеГрафика(" + Условие + ")"`), и условие, заданное только расширением системы компоновки `{...}`, диагностика не судит: условие неизвестно, а не отсутствует.

Таблица `База<Регистр>` узнаётся по имени, начинающемуся на `База` (`Base`). Перерасчёт с таким именем тоже будет проверен как таблица базы.

## Параметры

- `onlyInModulesWritingRegister` — если `true`, в модуле срабатывание остаётся, только если модуль пишет этот же регистр: в нём есть `Движения.<Регистр>` или `RegisterRecords.<Name>` (на любом получателе, например `ЭтотОбъект.Движения.<Регистр>`). Так отчёты, которым отбор по регистратору не нужен, не отмечаются. `Движения["<Регистр>"]` и упоминание в комментарии записью не считаются; ветки препроцессора не вычисляются, запись другим способом (например, через общий модуль) не распознаётся. Текст запроса без модуля параметр не ограничивает. По умолчанию `true`; `false` возвращает проверку всех модулей — решает только текст запроса.

## Примеры

### Срабатывание в модуле, который пишет регистр

```bsl
Движения.Начисления.Записать();

Запрос.Текст =
"ВЫБРАТЬ
|	ДанныеГрафика.НомерСтроки КАК НомерСтроки
|ИЗ
|	РегистрРасчета.Начисления.ДанныеГрафика(ВидРасчета = &ВидРасчета) КАК ДанныеГрафика";
```

### Предпочтительно при расчёте собственного набора записей

```bsl
Запрос.Текст =
"ВЫБРАТЬ
|	ДанныеГрафика.НомерСтроки КАК НомерСтроки
|ИЗ
|	РегистрРасчета.Начисления.ДанныеГрафика(Регистратор = &Регистратор) КАК ДанныеГрафика";
```

### История сотрудника по другим документам

В модуле, который не пишет регистр, срабатывания нет. В пишущем модуле такой запрос получит предупреждение, поскольку правило не отличает его от расчёта своего набора; если свой документ здесь не нужен, это можно показать явным исключением — срабатывания не будет. Отбор по своему регистратору в такой запрос не добавляется.

```bsl
Запрос.Текст =
"ВЫБРАТЬ
|	Т.Результат КАК Результат
|ИЗ
|	РегистрРасчета.Начисления.ФактическийПериодДействия(
|			Сотрудник = &Сотрудник
|				И Регистратор <> &Ссылка) КАК Т";
```

## Источники

Для отбора по регистратору нет прямого нормативного стандарта 1С. Требование — пункт списка ошибок экзамена «1С:Специалист по платформе», строки 125–126: «Отсутствие значений параметров в виртуальной таблице или использование вместо них условия «ГДЕ»». Стандарт «Обращения к виртуальным таблицам» требует передавать условия в параметры таблицы; чтение записей других документов он не запрещает и про регистратор не говорит.
