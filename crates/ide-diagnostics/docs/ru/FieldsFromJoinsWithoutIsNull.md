# Отсутствие проверки на NULL для полей из присоединяемых таблиц (FieldsFromJoinsWithoutIsNull)

## Описание диагностики

При использовании левого, правого или полного соединения поля из присоединяемой таблицы могут содержать `NULL`, если условие соединения не выполнено и подходящая запись отсутствует. Обращение к таким полям без обёртки `ЕСТЬNULL()` либо проверки `ЕСТЬ NULL` / `ЕСТЬ НЕ NULL` приводит к неожиданным результатам: любое сравнение с `NULL` (включая `NULL = NULL`) всегда возвращает ложь.

Для корректной обработки следует явно задать значение по умолчанию через функцию `ЕСТЬNULL()` или проверить значение оператором `ЕСТЬ NULL`.

Если данные гарантированно существуют в обеих таблицах, целесообразно заменить внешнее соединение на внутреннее (`ВНУТРЕННЕЕ СОЕДИНЕНИЕ`), что устраняет необходимость проверки на `NULL` и упрощает запрос.

Виртуальная таблица «ДанныеГрафика» регистра расчёта возвращает строку на каждую запись регистра, даже если график за период не заполнен. Тогда поля «<ресурс графика>ПериодДействия», «<ресурс графика>ФактическийПериодДействия», «<ресурс графика>ПериодРегистрации» и «<ресурс графика>БазовыйПериод» равны NULL. Замена соединения на внутреннее этот NULL не убирает: источника соединения нет. Такое поле следует обернуть в `ЕСТЬNULL()` или проверить оператором `ЕСТЬ NULL`. Отдельного стандарта для NULL из незаполненного графика нет.

Правило включено по умолчанию с версии 0.4.2: оно сообщает и о полях внешних соединений, и о полях «ДанныеГрафика».

### Когда поле внешнего соединения не сообщается

`NULL` отсутствующей строки опасен там, где доходит до результата запроса. Поэтому правило не сообщает о полях внешнего соединения в следующих случаях.

* **Поле только в условии.** Поле в `ГДЕ`, в условии `КОГДА` (включая выражение после `ВЫБОР` и значения `КОГДА` простого `ВЫБОР`) или в `ПО` до результата не доходит: условие только решает, попадёт ли строка в результат. Сравнение с `NULL` ложно, а `ЕСТЬ NULL` отсутствующую строку как раз отбирает — ни то ни другое не выводит `NULL` в выбранные значения. Отдельного предупреждения о том, что условие в `ГДЕ` делает левое соединение по сути внутренним, нет. Если то же поле выбирается в результат, сообщается употребление в результате.
* **Ветка `ТОГДА` под сравнением.** Если условие `КОГДА` прямо сравнивает поле присоединённой таблицы операцией `=`, `<>`, `<`, `<=`, `>` или `>=` с чем угодно (литералом, параметром, полем, выражением), ветка `ТОГДА` выполняется только при наличии строки, и поля этой же таблицы в ней не сообщаются. Сравнение может быть одним из операндов `И`. Не защищают: сравнение внутри `ИЛИ` или под `НЕ`; поле внутри функции или выражения (`ЕСТЬNULL(Т.Поле, 0) = 0`, `Т.Поле + 1 > 0`); `В`, `МЕЖДУ`, `ПОДОБНО`; голое булево поле; простой `ВЫБОР Т.Поле КОГДА 0 ТОГДА …`. Сравнение защищает только свою ветку: в следующих `КОГДА` и в `ИНАЧЕ` поля сообщаются, а поля другой присоединённой таблицы не защищены и в этой ветке.
* **Владелец своей табличной части.** Если к табличной части присоединён её собственный владелец (`Документ.X.Секция` и `Документ.X`, `Справочник.X.Секция` и `Справочник.X`) по условию `Секция.Ссылка = Владелец.Ссылка`, строка владельца есть всегда, и его поля не сообщаются. Это касается `Секция ЛЕВОЕ СОЕДИНЕНИЕ Владелец`, `Владелец ПРАВОЕ СОЕДИНЕНИЕ Секция` и стороны владельца в `ПОЛНОМ` соединении. Поля табличной части по-прежнему сообщаются в `Владелец ЛЕВОЕ СОЕДИНЕНИЕ Секция` и в `ПОЛНОМ` соединении: у владельца может не быть строк. Исключение действует, только если в запросе ровно эти две таблицы, а условие `ПО` состоит из этого равенства (порядок сторон и скобки не важны, повтор равенства через `И` допустим). Дополнительный отбор (`И Владелец.Проведен = ИСТИНА`), `ИЛИ`, другое поле или другой объект, третья таблица в соединении отменяют исключение.
* **Проверка в `ГДЕ`.** `Т.Поле ЕСТЬ НЕ NULL` или `НЕ (Т.Поле ЕСТЬ NULL)` в `ГДЕ` защищают выбранные поля этой таблицы. Обычное сравнение в `ГДЕ` выбранные поля не защищает.

В исключениях о владельце и о ветке `ТОГДА` псевдонимы таблиц латиницей сопоставляются без учёта регистра, кириллицей — как написаны. Проверка в `ГДЕ` сопоставляет псевдоним точно как написан, в том числе латиницей: `ГДЕ курьеры.Транспорт ЕСТЬ НЕ NULL` при псевдониме `Курьеры` поля не защищает.

Эти исключения доказывают наличие строки соединения и к «ДанныеГрафика» не относятся: там `NULL` бывает и в существующей строке. Значение графика в условии `ГДЕ` или `КОГДА` сообщается, а сравнение другого поля строки (например, `НомерСтроки`) значение графика не защищает.

## Примеры

### Неправильно

```sdbl
ВЫБРАТЬ
    Заказы.Номер КАК НомерЗаказа,
    Оплаты.Сумма КАК СуммаОплаты
ИЗ
    Документ.ЗаказПокупателя КАК Заказы
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.Оплаты КАК Оплаты
    ПО Заказы.Ссылка = Оплаты.Заказ
```

### Правильно (функция ЕСТЬNULL)

```sdbl
ВЫБРАТЬ
    Заказы.Номер КАК НомерЗаказа,
    ЕСТЬNULL(Оплаты.Сумма, 0) КАК СуммаОплаты
ИЗ
    Документ.ЗаказПокупателя КАК Заказы
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.Оплаты КАК Оплаты
    ПО Заказы.Ссылка = Оплаты.Заказ
```

### Правильно (оператор ЕСТЬ NULL в выражении ВЫБОР)

```sdbl
ВЫБРАТЬ
    Заказы.Номер КАК НомерЗаказа,
    ВЫБОР КОГДА Оплаты.Сумма ЕСТЬ NULL ТОГДА 0
    ИНАЧЕ Оплаты.Сумма
    КОНЕЦ КАК СуммаОплаты
ИЗ
    Документ.ЗаказПокупателя КАК Заказы
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.Оплаты КАК Оплаты
    ПО Заказы.Ссылка = Оплаты.Заказ
```

### Неправильно (арифметика с полем соединения)

`NULL` ставки делает `NULL` всю сумму:

```sdbl
ВЫБРАТЬ
	Товары.Сумма * Ставки.Ставка КАК Сумма
ИЗ
	Документ.Заказ.Товары КАК Товары
		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.Ставки КАК Ставки
		ПО Товары.Номенклатура = Ставки.Номенклатура
```

### Правильно (арифметика через ЕСТЬNULL)

```sdbl
ВЫБРАТЬ
	Товары.Сумма * ЕСТЬNULL(Ставки.Ставка, 0) КАК Сумма
ИЗ
	Документ.Заказ.Товары КАК Товары
		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.Ставки КАК Ставки
		ПО Товары.Номенклатура = Ставки.Номенклатура
```

### Правильно (ветка ТОГДА под сравнением поля той же таблицы)

Без строки ставки условие `КОГДА` ложно, и деление не выполняется:

```sdbl
ВЫБРАТЬ
	ВЫБОР
		КОГДА Ставки.Ставка <> 0
			ТОГДА Товары.Сумма / Ставки.Ставка
		ИНАЧЕ 0
	КОНЕЦ КАК Сумма
ИЗ
	Документ.Заказ.Товары КАК Товары
		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.Ставки КАК Ставки
		ПО Товары.Номенклатура = Ставки.Номенклатура
```

### Правильно (владелец табличной части)

У каждой строки табличной части есть документ-владелец:

```sdbl
ВЫБРАТЬ
	Товары.Номенклатура КАК Номенклатура,
	Заказ.Дата КАК Дата
ИЗ
	Документ.Заказ.Товары КАК Товары
		ЛЕВОЕ СОЕДИНЕНИЕ Документ.Заказ КАК Заказ
		ПО Товары.Ссылка = Заказ.Ссылка
```

### Неправильно (значение данных графика без ЕСТЬNULL)

```sdbl
ВЫБРАТЬ
	ДанныеГрафика.НомерСтроки КАК НомерСтроки,
	ДанныеГрафика.ЧасыФактическийПериодДействия * 100 КАК Сумма
ИЗ
	РегистрРасчета.Начисления.ДанныеГрафика(Регистратор = &Регистратор) КАК ДанныеГрафика
```

### Правильно (значение данных графика через ЕСТЬNULL)

```sdbl
ВЫБРАТЬ
	ДанныеГрафика.НомерСтроки КАК НомерСтроки,
	ЕСТЬNULL(ДанныеГрафика.ЧасыФактическийПериодДействия, 0) КАК Часы
ИЗ
	РегистрРасчета.Начисления.ДанныеГрафика(Регистратор = &Регистратор) КАК ДанныеГрафика
```
