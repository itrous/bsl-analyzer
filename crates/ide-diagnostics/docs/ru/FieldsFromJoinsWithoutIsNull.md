# Отсутствие проверки на NULL для полей из присоединяемых таблиц (FieldsFromJoinsWithoutIsNull)

## Описание диагностики

При использовании левого, правого или полного соединения поля из присоединяемой таблицы могут содержать `NULL`, если условие соединения не выполнено и подходящая запись отсутствует. Обращение к таким полям без обёртки `ЕСТЬNULL()` либо проверки `ЕСТЬ NULL` / `ЕСТЬ НЕ NULL` приводит к неожиданным результатам: любое сравнение с `NULL` (включая `NULL = NULL`) не истинно, его результат неопределён.

Для корректной обработки следует явно задать значение по умолчанию через функцию `ЕСТЬNULL()` или проверить значение оператором `ЕСТЬ NULL`.

Если данные гарантированно существуют в обеих таблицах, целесообразно заменить внешнее соединение на внутреннее (`ВНУТРЕННЕЕ СОЕДИНЕНИЕ`), что устраняет необходимость проверки на `NULL` и упрощает запрос.

Виртуальная таблица «ДанныеГрафика» регистра расчёта возвращает строку на каждую запись регистра, даже если график за период не заполнен. Тогда поля «<ресурс графика>ПериодДействия», «<ресурс графика>ФактическийПериодДействия», «<ресурс графика>ПериодРегистрации» и «<ресурс графика>БазовыйПериод» равны NULL. Замена соединения на внутреннее этот NULL не убирает: источника соединения нет. Такое поле следует обернуть в `ЕСТЬNULL()` или проверить оператором `ЕСТЬ NULL`. Отдельного стандарта для NULL из незаполненного графика нет.

Правило включено по умолчанию с версии 0.4.2: оно сообщает и о полях внешних соединений, и о полях «ДанныеГрафика».

### Когда поле внешнего соединения не сообщается

`NULL` отсутствующей строки опасен там, где доходит до результата запроса. Чтобы это определить, правило подставляет `NULL` вместо прямых полей отсутствующей строки и вычисляет условия в трёхзначной логике: условие истинно, ложно или неопределено. Сравнение с `NULL` неопределено. Это значит «не истинно», но не «ложь»: `НЕ` над неопределённым условием остаётся неопределённым. Параметры, поля других таблиц и всё, что правило не умеет вычислить, неизвестны: такое условие может иметь любой исход. Сам запрос при этом не выполняется, поэтому результат — консервативное доказательство, а не значение из базы.

Правило не сообщает о полях внешнего соединения в следующих случаях.

* **Поле только в условии.** Поле в `ГДЕ`, в условии `КОГДА` (включая выражение после `ВЫБОР` и значения `КОГДА` простого `ВЫБОР`) или в `ПО` до результата не доходит: условие только решает, попадёт ли строка в результат. Сравнение с `NULL` не истинно, а `ЕСТЬ NULL` отсутствующую строку как раз отбирает — ни то ни другое не выводит `NULL` в выбранные значения. Если то же поле выбирается в результат, сообщается употребление в результате, кроме случаев ниже.
* **Ветка `ТОГДА`, недостижимая без строки.** Если условие `КОГДА` при подстановке не может быть истинным, поля этой таблицы в ветке `ТОГДА` не сообщаются. Так работают сравнения `=`, `<>`, `<`, `<=`, `>`, `>=` с чем угодно, `МЕЖДУ`, `ПОДОБНО`, `ССЫЛКА`, `В`, `В ИЕРАРХИИ`, голое булево поле, `ЕСТЬ НЕ NULL`, `НЕ` над ними (с оговоркой о пустых списках ниже) и простой `ВЫБОР Т.Поле КОГДА 0 ТОГДА …`. `И` защищает, если не может быть истинным хотя бы один его операнд, `ИЛИ` — если не может ни один: `Т.Поле = 0 ИЛИ &Флаг` ветку не защищает. Поля другой присоединённой таблицы в этой ветке не защищены.
* **Ветки после гарантированно истинного условия.** Если условие `КОГДА` при подстановке истинно всегда (`Т.Поле ЕСТЬ NULL`, `Т.Поле ЕСТЬ NULL ИЛИ &Флаг`, `ЕСТЬNULL(Т.Поле, 0) = 0` при известном числовом типе), следующие `КОГДА` и `ИНАЧЕ` без строки не выполняются, и поля этой таблицы в них не сообщаются. В своей ветке `ТОГДА` такое условие ничего не защищает: `КОГДА Т.Сотрудник ЕСТЬ NULL ТОГДА Т.ВидРасчета` сообщается, здесь значение равно `NULL` всегда. Неопределённое условие истинным не считается: `КОГДА Т.Поле = 0 ТОГДА 0 ИНАЧЕ Т.Сумма` и простой `ВЫБОР Т.Поле КОГДА 0 ТОГДА 0 ИНАЧЕ Т.Сумма` сообщают `Т.Сумма`.
* **Что пропускает `NULL`.** `NULL` дают прямое поле таблицы, арифметика `+`, `-`, `*`, `/`, `%`, унарные `+` и `-` и `РАЗНОСТЬДАТ`, если `NULL` стоит хотя бы в одной из дат; неизвестная вторая дата этого не отменяет. Другая функция свойства «пропускает `NULL`» не получает: `ЕСТЬNULL`, `ВЫБОР` как значение, `ПРЕДСТАВЛЕНИЕ` (от `NULL` даёт пустую строку), `КОЛИЧЕСТВО` и неизвестная функция считаются неизвестными. Поэтому `ПРЕДСТАВЛЕНИЕ(Т.Поле) = ""` ветку не защищает.
* **`ЕСТЬNULL` с вычисляемой заменой.** `ЕСТЬNULL(Т.Поле, З)` без строки равно `З`, только если известен тип поля и значение `З` при приведении к нему заведомо не меняется: целочисленный литерал, помещающийся в известные разряды числа (ноль — при любых квалификаторах); булев литерал для булева поля; `ДАТАВРЕМЯ(1, 1, 1)` для даты; строка, помещающаяся в известную длину реальной таблицы, или любая строка при неограниченной длине (`Длина = 0`). Для прямого поля временной таблицы с известным строковым типом замена сохраняется целиком, даже если длиннее поля: так показал опыт на платформе, на реальные таблицы это не переносится. Неизвестным результат остаётся при неизвестном, составном или нераскрытом определяемом типе, для дробного литерала, литерала со знаком, неподходящего или непредставимого литерала, строки неизвестной длины и для параметра, который сам может быть `NULL`. Прочие вызовы `ДАТАВРЕМЯ` тоже неизвестны. Разные по написанию строки не считаются неравными: это зависит от правил сравнения в базе, поэтому такое сравнение неизвестно.
* **Без типов поля такие условия не вычисляются.** Тип не угадывается по имени поля. Без метаданных `КОГДА ЕСТЬNULL(Курсы.Курс, 0) = 0 ТОГДА 0 ИНАЧЕ Курсы.Курс` и `КОГДА ЕСТЬNULL(ОС.ДатаСписания, ДАТАВРЕМЯ(1, 1, 1)) <> ДАТАВРЕМЯ(1, 1, 1) ТОГДА ОС.ДатаСписания` остаются сообщениями; с загруженными метаданными и подходящим типом они снимаются.
* **`В` и `В ИЕРАРХИИ`.** `Т.Поле В (…)` и `Т.Поле В ИЕРАРХИИ (…)` без строки не истинны при любом списке. `НЕ` над ними и `НЕ В` защищают, только если в списке есть явный литерал (в том числе `NULL` или `ЗНАЧЕНИЕ(Справочник.X.ПустаяСсылка)`): тогда условие неопределено. Параметр, несколько параметров и вложенный запрос могут оказаться пустыми, `NULL` в пустом списке даёт ложь, и `НЕ` делает её истиной, поэтому `НЕ (Т.Поле В (&Значения))` не защищает. Значение параметра в коде BSL и вложенный запрос не анализируются.
* **Владелец своей табличной части.** Если к табличной части присоединён её собственный владелец (`Документ.X.Секция` и `Документ.X`, `Справочник.X.Секция` и `Справочник.X`) по условию `Секция.Ссылка = Владелец.Ссылка`, строка владельца есть у каждой строки секции, и его прямые поля не сообщаются. Это касается `Секция ЛЕВОЕ СОЕДИНЕНИЕ Владелец`, `Владелец ПРАВОЕ СОЕДИНЕНИЕ Секция` и стороны владельца в `ПОЛНОМ` соединении. Третьи таблицы исключению не мешают, пока сама секция обязательна. Поля табличной части по-прежнему сообщаются в `Владелец ЛЕВОЕ СОЕДИНЕНИЕ Секция` и в `ПОЛНОМ` соединении: у владельца может не быть строк. Исключение отменяется, если другое соединение делает секцию необязательной (она на необязательной стороне внешнего `ЛЕВОГО`, `ПРАВОГО` или `ПОЛНОГО`), если владелец соединён вместе с другой таблицей одним операндом, а также при дополнительном отборе в `ПО` (`И Владелец.Проведен = ИСТИНА`), `ИЛИ`, другом поле или другом объекте. Порядок сторон и скобки не важны, повтор равенства через `И` допустим.
* **Условие `ГДЕ`, отсекающее строку.** Если условие `ГДЕ` при подстановке не может быть истинным, строка без пары в результат не попадает, и прямые поля этой таблицы не сообщаются. Достаточно одного конъюнкта верхнего уровня: `Цены.Период МЕЖДУ &Начало И &Конец`, `Док.Проведен И Цены.ТипЦен В (&ТипыЦен)`, `Т.Поле ЕСТЬ НЕ NULL`, `НЕ (Т.Поле ЕСТЬ NULL)`. Конъюнкт с `ИЛИ` вычисляется целиком: `Т.Поле ЕСТЬ НЕ NULL ИЛИ &Флаг` и `Т.Поле = 0 ИЛИ &Флаг` не защищают, а `Т.Поле = 0 ИЛИ Т.Другое = 1` защищает. Доказательство относится только к таблице условия: в `ПОЛНОМ` соединении условие на одну сторону не защищает другую, не защищает оно и другие присоединённые таблицы. Не считаются условием `ГДЕ` внешнего запроса `ИМЕЮЩИЕ`, `ПО` и псевдоним из вложенного запроса. Отдельного предупреждения о том, что `ГДЕ` делает соединение по сути внутренним, нет.
* **Разыменование остаётся сообщением.** Все исключения про наличие строки и условие `ГДЕ` относятся к прямым полям. `Т.Ссылка.Реквизит`, `(Т.Поле).Реквизит` и `ВЫРАЗИТЬ(Т.Поле КАК Справочник.X).Реквизит` сообщаются и при существующей строке, потому что ссылка может быть пустой. Такое выражение в условии доказательством не считается.

В условиях `ВЫБОР` и в исключении о владельце псевдонимы таблиц латиницей сопоставляются без учёта регистра, кириллицей — как написаны. Условие `ГДЕ` сопоставляет псевдоним точно как написан, в том числе латиницей: `ГДЕ курьеры.Транспорт ЕСТЬ НЕ NULL` при псевдониме `Курьеры` поля не защищает.

Эти исключения доказывают наличие строки соединения и к значениям «ДанныеГрафика» не относятся: там `NULL` бывает и в существующей строке. Значение графика в условии `ГДЕ` или `КОГДА` сообщается, а сравнение другого поля строки (например, `НомерСтроки`) значение графика не защищает.

## Примеры

### Неправильно

```sdbl
ВЫБРАТЬ
    Заказы.Номер КАК НомерЗаказа,
    Оплаты.Сумма КАК СуммаОплаты
ИЗ
    Документ.ЗаказПокупателя КАК Заказы
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.Оплаты КАК Оплаты
    ПО Заказы.Ссылка = Оплаты.Заказ
```

### Правильно (функция ЕСТЬNULL)

```sdbl
ВЫБРАТЬ
    Заказы.Номер КАК НомерЗаказа,
    ЕСТЬNULL(Оплаты.Сумма, 0) КАК СуммаОплаты
ИЗ
    Документ.ЗаказПокупателя КАК Заказы
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.Оплаты КАК Оплаты
    ПО Заказы.Ссылка = Оплаты.Заказ
```

### Правильно (оператор ЕСТЬ NULL в выражении ВЫБОР)

```sdbl
ВЫБРАТЬ
    Заказы.Номер КАК НомерЗаказа,
    ВЫБОР КОГДА Оплаты.Сумма ЕСТЬ NULL ТОГДА 0
    ИНАЧЕ Оплаты.Сумма
    КОНЕЦ КАК СуммаОплаты
ИЗ
    Документ.ЗаказПокупателя КАК Заказы
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.Оплаты КАК Оплаты
    ПО Заказы.Ссылка = Оплаты.Заказ
```

### Неправильно (арифметика с полем соединения)

`NULL` ставки делает `NULL` всю сумму:

```sdbl
ВЫБРАТЬ
	Товары.Сумма * Ставки.Ставка КАК Сумма
ИЗ
	Документ.Заказ.Товары КАК Товары
		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.Ставки КАК Ставки
		ПО Товары.Номенклатура = Ставки.Номенклатура
```

### Правильно (арифметика через ЕСТЬNULL)

```sdbl
ВЫБРАТЬ
	Товары.Сумма * ЕСТЬNULL(Ставки.Ставка, 0) КАК Сумма
ИЗ
	Документ.Заказ.Товары КАК Товары
		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.Ставки КАК Ставки
		ПО Товары.Номенклатура = Ставки.Номенклатура
```

### Правильно (ветка ТОГДА под сравнением поля той же таблицы)

Без строки ставки условие `КОГДА` не истинно, и деление не выполняется:

```sdbl
ВЫБРАТЬ
	ВЫБОР
		КОГДА Ставки.Ставка <> 0
			ТОГДА Товары.Сумма / Ставки.Ставка
		ИНАЧЕ 0
	КОНЕЦ КАК Сумма
ИЗ
	Документ.Заказ.Товары КАК Товары
		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.Ставки КАК Ставки
		ПО Товары.Номенклатура = Ставки.Номенклатура
```

### Правильно (ветка ИНАЧЕ после гарантированно истинного условия)

Без строки курса условие равно `0 = 0`, поэтому `ИНАЧЕ` выполняется только при существующей строке. Снятие сообщения требует известного числового типа `Курсы.Курс`:

```sdbl
ВЫБРАТЬ
	ВЫБОР
		КОГДА ЕСТЬNULL(Курсы.Курс, 0) = 0
			ТОГДА 0
		ИНАЧЕ Док.Сумма * Курсы.Курс / Курсы.Кратность
	КОНЕЦ КАК СуммаРуб
ИЗ
	Документ.Заказ КАК Док
		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.КурсыВалют КАК Курсы
		ПО Док.Валюта = Курсы.Валюта
```

### Правильно (условие ГДЕ отсекает строку без пары)

```sdbl
ВЫБРАТЬ
	Док.Ссылка КАК Ссылка,
	Цены.Цена КАК Цена
ИЗ
	Документ.Заказ КАК Док
		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.Цены КАК Цены
		ПО Док.Номенклатура = Цены.Номенклатура
ГДЕ
	Цены.Период МЕЖДУ &Начало И &Конец
```

### Правильно (владелец табличной части)

У каждой строки табличной части есть документ-владелец, третья таблица этому не мешает:

```sdbl
ВЫБРАТЬ
	Товары.Номенклатура КАК Номенклатура,
	Заказ.Дата КАК Дата
ИЗ
	Документ.Заказ.Товары КАК Товары
		ЛЕВОЕ СОЕДИНЕНИЕ Документ.Заказ КАК Заказ
		ПО Товары.Ссылка = Заказ.Ссылка
```

### Неправильно (значение данных графика без ЕСТЬNULL)

```sdbl
ВЫБРАТЬ
	ДанныеГрафика.НомерСтроки КАК НомерСтроки,
	ДанныеГрафика.ЧасыФактическийПериодДействия * 100 КАК Сумма
ИЗ
	РегистрРасчета.Начисления.ДанныеГрафика(Регистратор = &Регистратор) КАК ДанныеГрафика
```

### Правильно (значение данных графика через ЕСТЬNULL)

```sdbl
ВЫБРАТЬ
	ДанныеГрафика.НомерСтроки КАК НомерСтроки,
	ЕСТЬNULL(ДанныеГрафика.ЧасыФактическийПериодДействия, 0) КАК Часы
ИЗ
	РегистрРасчета.Начисления.ДанныеГрафика(Регистратор = &Регистратор) КАК ДанныеГрафика
```
