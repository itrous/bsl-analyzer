# Объявленный язык с пустым переводом (MultilingualStringHasEmptyTranslation)

## Описание диагностики

В строке `НСтр("ru = 'Остаток'; uk = ''")` язык `uk` объявлен, но перевод для него пуст. Платформа такой литерал принимает без ошибок, поэтому дефект видит только анализатор: при работе под языком `uk` функция вернёт пустую строку, и интерфейс молча потеряет текст.

Правило срабатывает, когда:

- язык входит в список объявленных (настройка `declaredLanguages` правила `MultilingualStringHasAllDeclaredLanguages`, по умолчанию только `ru`);
- запись языка есть в литерале, а между кавычками ничего нет;
- значение из одних пробелов считается пустым: пробел не является переводом;
- в том же литерале есть запись с непустым текстом на другом языке: текст существует, но для этого языка потерян.

Не отмечаются: литерал, пустой на всех языках (`ru = ''; uk = ''` - намеренно пустая строка, ничего не теряется), запись, у которой после закрывающей кавычки идёт не `;` и не конец текста (`ru='' на '`), непустые значения, пустые значения языков, которые не объявлены, и вызовы `НСтр`, чей первый аргумент не одиночный строковый литерал (переменная, конкатенация) - его текст статически неизвестен. Удвоенная кавычка внутри значения (`''`) - это экранированная кавычка, а не пустое значение.

Отличие от `MultilingualStringHasAllDeclaredLanguages`: та диагностика находит язык, которого в литерале нет совсем; эта - язык, который указан, но не заполнен. На одной записи они не срабатывают одновременно. В отличие от первой, пустой перевод отмечается и внутри `СтрШаблон`.

## Примеры

Конфигурация поддерживает языки `ru` и `uk`.

Неправильно:

```bsl
Сообщение = НСтр("ru = 'Остаток'; uk = ''");
Сообщение = НСтр("ru = 'Остаток'; uk = ' '");
```

Правильно:

```bsl
Сообщение = НСтр("ru = 'Остаток'; uk = 'Залишок'");
```
