# Несоответствие типов (TypeMismatch)

## Описание диагностики

Эта диагностика срабатывает, когда выведенный тип аргумента вызова несовместим с типами параметров всех arity-совместимых кандидатов.

В данный момент `TypeMismatch` активна для проверки аргументов вызова. При вызове функции или метода анализатор собирает все кандидатские сигнатуры, оценивает арность и применимость, и генерирует несоответствие только если вызов отклонен.

### Процесс разрешения кандидатов

Анализатор разрешает каждый вызов в одно из трех взаимоисключающих состояний выбора:

1. **Единственный кандидат**: После ранжирования остается ровно один лучший известный подходящий кандидат. Для проверки используются типы его параметров.
2. **Неоднозначные кандидаты**: Либо несколько известных подходящих кандидатов делят лучший счет, либо один или несколько неопределенных кандидатов выживают при отсутствии известных подходящих. Если выживает хотя бы один кандидат, `TypeMismatch` не генерируется.
3. **Отклоненные кандидаты**: Ни один кандидат не выживает. Аргументы несовместимы со всеми arity-совместимыми сигнатурами, или ни один кандидат не подходит по арности. `TypeMismatch` генерируется только при отклонении по типам, для первого несовместимого аргумента детерминированного наименее несовместимого отклоненного кандидата.

### Ключевые правила

- **Разделение по JSDoc**: Случаи, когда ожидаемый тип получен из JSDoc-комментариев, выделяются в отдельную диагностику `TypeMismatchByDocComment`. Это позволяет отличать строгие платформенные типы от пользовательской документации.
- **Неопределенные аргументы**: Аргумент или параметр типа `Unknown` считается неопределенным и сам по себе не вызывает `TypeMismatch`. Другие конкретные несовместимые аргументы по-прежнему могут отклонить вызов.
- **Пересекающиеся типы**: Диагностика срабатывает, только когда наборы ожидаемых и полученных типов не имеют общего члена. Значение типа `Число | Неопределено`, выведенное из веток кода, в параметре `Число` не отмечается: часть его значений подходит. Если таких аргументов в вызове несколько, отмечается первый аргумент без общего члена.
- **Длинные объединения**: В сообщении остаются первые три члена объединения, остальные сворачиваются в « | … и ещё N». Набор находок считается по полным меткам до сокращения, поэтому длинное объединение отмечается ровно тогда, когда отмечалось бы полное. Если после сокращения обе стороны читаются одинаково, печатаются полные метки. Тип, который сам не является объединением, печатается целиком, даже если в его метке есть ` | `. Другие представления типа остаются полными. `TypeMismatchByDocComment` сокращает сообщение так же.
- **Неоднозначность**: Неоднозначность при разрешении типов не приводит к `TypeMismatch`. Диагностика срабатывает только тогда, когда выбор кандидата явно отклонен.

## Примеры

```bsl
// ТаблицаЗначений.Вставить ожидает Число в качестве индекса
ТаблицаЗначений.Вставить("не число"); // Несоответствие типов: ожидалось 'Число', получено 'Строка'

Позиция = Неопределено;
Если Условие Тогда
    Позиция = 5;
КонецЕсли;
Результат = Лев("abc", Позиция); // Нет TypeMismatch: тип 'Число | Неопределено' пересекается с 'Число'; это случай подсказки PossiblyUndefinedValue
```
