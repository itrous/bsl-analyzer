# Обращение к коду, недоступному в контексте исполнения (ModuleAccessibility)

## Описание диагностики

Пользовательский код, как и платформенный API, доступен не во всех средах исполнения. Диагностика сообщает о двух видах нарушений:

- **Вызов общего модуля из среды, для которой он не компилируется.** Серверный общий модуль без флага «Вызов сервера» нельзя вызвать из клиентского кода; клиентский общий модуль не существует на сервере. Модуль с флагом «Вызов сервера» из клиента вызывать можно — это штатный удалённый вызов, и такой вызов не диагностируется.
- **Вызов локального метода поперёк директив компиляции.** Код, исполняющийся на сервере, не может вызвать метод за директивой `&НаКлиенте` — на сервере такого символа нет. Обратное направление (клиентский метод формы вызывает `&НаСервере`-метод) — это штатный серверный вызов формы и не диагностируется. В модуле управляемой формы вызов через `ЭтотОбъект`/`ЭтаФорма` — тот же вызов локального метода и проверяется одинаково с вызовом по имени.

Множество сред точки вызова вычисляется так же, как в `UnavailableInEnvironment`: среды модуля ∩ директива компиляции ∩ сужение препроцессором `#Если` (включая области вокруг целых методов). В квалификаторе сообщения перечисляются только среды-нарушители — по аналогии с вердиктами 1C:EDT «Module 'X' is not accessible at client» и «Procedure 'X' is not defined [Server]».

Флаги вызываемого общего модуля берутся из конфигурации, видимой вызывающему: расширение, принявшее модуль, замещает его флаги целиком, поэтому включённый в расширении «Вызов сервера» снимает диагностику для кода этого расширения.

Ограничения (сознательно консервативные): перехватчики расширений (`&Вместо`/`&Перед`/`&После`, `&ИзменениеИКонтроль`) не проверяются; вызовы через переменную, содержащую модуль (`М = ОбщегоНазначения.ОбщийМодуль("Имя"); М.Метод()`), не проверяются — поток управления выбирает модуль динамически; мобильный клиент, внешнее соединение и толстый клиент (обычное приложение) по умолчанию не входят в проверяемое множество сред; в среды вызывающего кода толстый клиент (обычное приложение) входит только при включённой поддержке обычного приложения, кроме кода, который существует в этом клиенте по своим метаданным (модуль обычной формы, модуль обычного приложения, общий модуль с флагом «Клиент (обычное приложение)»), а флаг вызываемого общего модуля «Клиент (обычное приложение)» учитывается всегда: модуль, отмеченный только этим флагом, недоступен ни в управляемых клиентах, ни на сервере.

## Настройка

Проверяемое множество сред задаётся списком `checked_environments` в секции `[features]` файла `bsl-analyzer.toml` — общим для `ModuleAccessibility` и `UnavailableInEnvironment`; подробности и пример в документации `UnavailableInEnvironment`.

## Примеры

Неправильно:

```bsl
// ОбщийМодуль.Серверный: Сервер = Истина, ВызовСервера = Ложь
&НаКлиенте
Процедура Сохранить()
    Серверный.Записать(); // модуль недоступен на клиенте
КонецПроцедуры
```

```bsl
&НаКлиенте
Процедура Показать()
КонецПроцедуры

&НаСервере
Процедура Обработать()
    Показать(); // на сервере метода не существует
КонецПроцедуры
```

Правильно:

```bsl
// ОбщийМодуль.СерверныйВызовСервера: Сервер = Истина, ВызовСервера = Истина
&НаКлиенте
Процедура Сохранить()
    СерверныйВызовСервера.Записать(); // штатный удалённый вызов
КонецПроцедуры
```
