# Выполнение запроса в цикле (CreateQueryInCycle)

## Описание диагностики

Создание и выполнение запроса внутри цикла -- грубая ошибка производительности. Каждая итерация порождает обращение к СУБД, что приводит к многократному увеличению времени выполнения и нагрузки на сервер. Вместо этого следует формировать запрос так, чтобы все необходимые данные извлекались за одно обращение, используя параметры-списки или временные таблицы.

## Примеры

Неправильно:

```bsl
МассивНоменклатуры = Новый Массив;
ИтоговаяСумма = 0;

Для Каждого ТекЭлемент Из МассивНоменклатуры Цикл
    Запрос = Новый Запрос;
    Запрос.Текст =
        "ВЫБРАТЬ
        |   Товары.Цена
        |ИЗ
        |   Справочник.Номенклатура КАК Товары
        |ГДЕ
        |   Товары.Ссылка = &ТекСсылка";
    Запрос.УстановитьПараметр("ТекСсылка", ТекЭлемент);
    Выборка = Запрос.Выполнить().Выбрать();
    Пока Выборка.Следующий() Цикл
        ИтоговаяСумма = ИтоговаяСумма + Выборка.Цена;
    КонецЦикла;
КонецЦикла;
```

Правильно:

```bsl
МассивНоменклатуры = Новый Массив;

Запрос = Новый Запрос;
Запрос.Текст =
    "ВЫБРАТЬ
    |   СУММА(Товары.Цена) КАК ИтогоЦена
    |ИЗ
    |   Справочник.Номенклатура КАК Товары
    |ГДЕ
    |   Товары.Ссылка В (&СписокНоменклатуры)";
Запрос.УстановитьПараметр("СписокНоменклатуры", МассивНоменклатуры);

Выборка = Запрос.Выполнить().Выбрать();
Пока Выборка.Следующий() Цикл
    ИтоговаяСумма = Выборка.ИтогоЦена;
КонецЦикла;
```

## Что считается выполнением запроса

Диагностика включена по умолчанию, важность — критическая, действует во всех модулях. Настройки
те же, что у остальных правил: секция `[diagnostics]` и переопределения важности.

Находка ставится на вызов в теле цикла `Для`, `Для Каждого` или `Пока`, в процедуре, функции или
коде модуля. Заголовок внешнего цикла телом цикла не считается.

- `Запрос.Выполнить()` и `Запрос.ВыполнитьПакет()` — у получателя, который на всех путях является
  запросом. Текст запроса и его параметры знать не нужно.
- `ПостроительЗапроса.Выполнить()` и `ПостроительОтчета.Выполнить()`. Пакета у них нет.
- Вызов локальной процедуры или функции этого же модуля, из которой выполнение запроса достижимо
  напрямую или через другие локальные методы, в том числе рекурсивно. Длина цепочки не ограничена,
  порядок объявлений не важен.

Правило смотрит только на один модуль и только на то, что доказано. Находки нет, если тип получателя
неизвестен или смешан с другими типами, если вызов не удалось разрешить, если метод другого модуля
или вызов по строке. Отсутствие находки не означает, что такой код не обращается к базе данных.
`ВыполнитьПакетСПромежуточнымиДанными` правило не учитывает.

Находка на вызове локального метода, из которого достижимо выполнение запроса, оформлена отдельным
кодом `LocalCallWithQueryInCycle` с пониженной важностью
(см. [LocalCallWithQueryInCycle](LocalCallWithQueryInCycle.md)); здесь остаётся само выполнение
запроса в теле цикла.

## Обоснованное исключение

Стандарт допускает обоснованные исключения. Если запрос в помощнике нужен намеренно, подавите именно
это выполнение: директива перед ним снимает находки со всех цепочек, основанных только на нём.
Пояснение пишется отдельным комментарием, а не в список кодов директивы: там каждое слово считается
кодом.

```bsl
Процедура Прочитать()
    Запрос = Новый Запрос;
    // Порционное чтение необходимо для ограничения объёма обработки.
    // bsl-analyzer:disable-next-line CreateQueryInCycle
    Запрос.ВыполнитьПакет();
КонецПроцедуры
```

Директива относится к строке, на которой начинается вызов: директива перед `Запрос.Текст = ...` или
другой строкой находку не снимает. Если в помощнике два выполнения и подавлено одно, цепочки остаются
в находках из-за второго.

Подавление в вызывающем коде скрывает только находку на этом месте и не разрешает помощник другим
вызывающим. Находка на вызове идёт кодом `LocalCallWithQueryInCycle`, поэтому директива называет
его:

```bsl
// bsl-analyzer:off LocalCallWithQueryInCycle
Для Каждого Элемент Из Элементы Цикл
    Прочитать();
КонецЦикла;
// bsl-analyzer:on LocalCallWithQueryInCycle
```

Директива на одной строке заголовка цикла остальные строки тела не подавляет. `off` без парного `on`
действует до конца файла, `on` без парного `off` ничего не подавляет. Отдельного замечания о
неиспользованной директиве нет. `@skip-check` — обычный комментарий.
