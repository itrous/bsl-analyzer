# Устаревший API платформы (DeprecatedPlatformApi)

## Описание диагностики

Диагностика сообщает об обращениях к API платформы 1С:Предприятие, которые помечены в документации платформы как устаревшие.

Проверка покрывает устаревшие глобальные функции, глобальные методы, типы платформы и атрибуты платформы, для которых известно рекомендуемое средство замены. Текст сообщения называет конкретный устаревший API и сохраняет замену из реестра фактов платформы.

`DeprecatedMethodCall` остается отдельной диагностикой для методов прикладного кода, устаревших по комментариям документации. `GetFormMethod` также остается отдельной диагностикой и может срабатывать вместе с этой диагностикой для `ПолучитьФорму()` / `GetForm()`.

## Параметры

- `exclude` (список строк, по умолчанию пустой) — имена устаревших средств, о которых не сообщать. Имя пишется так, как сообщение называет устаревшее средство, без типа-владельца: `Получить`, а не `HTTPСоединение.Получить`. Годится русское или английское написание, регистр не важен. Одно написание подавляет оба: `ТекущаяДата` подавляет и `CurrentDate()`. Имя участника подавляет его у всех типов-владельцев. Остальные срабатывания остаются.

Пример: показывать все устаревшие средства, кроме `ТекущаяДата` и методов обработки ошибок:

```toml
[diagnostics.parameters.DeprecatedPlatformApi]
exclude = ["ТекущаяДата", "КраткоеПредставлениеОшибки", "ПодробноеПредставлениеОшибки", "ПоказатьИнформациюОбОшибке"]
```

`DeprecatedPlatformApi = false` выключает проверку целиком. `exclude` только сужает включённую проверку, и в одном TOML эти записи не совмещаются: ключ `DeprecatedPlatformApi` и таблица `[diagnostics.parameters.DeprecatedPlatformApi]` — повтор одного ключа.

Неизвестное имя, в том числе опечатку, и элемент не-строку загрузчик конфигурации сообщает предупреждением и пропускает; остальные имена списка действуют. Значение не-массив (`exclude = "ТекущаяДата"`) сообщается и игнорируется целиком.

Срабатывание «Имя перечисления» подавляет имя перечисления перед точкой: `ОриентацияМетокДиаграммы` подавляет `ОриентацияМетокДиаграммы.Вертикальная`. Имя из сообщения подавляет такое срабатывание, только если это имя само устаревшее средство (`Авто`); при неизвестном имени (`Вертикальная`) загрузчик предупреждает.

Ключи `DeprecatedCurrentDate`, `DeprecatedErrorProcessing` и другие коды, удалённые в v0.2.50, не поддерживаются и ничего не выключают. Если имена средств выводятся из реестра устаревших средств, предупреждение о таком ключе показывает готовую запись `exclude`, например `exclude = ["ТекущаяДата"]` для `DeprecatedCurrentDate`. Для остальных удалённых кодов предупреждение только называет параметр `exclude`.

## Примеры

Неправильно:

```bsl
ДатаОперации = ТекущаяДата();
Позиция = Найти("abcdef", "cd");
Форма = ПолучитьФорму("Форма");
Описание = ПодробноеПредставлениеОшибки(ИнформацияОбОшибке());
```

Правильно:

```bsl
ДатаОперации = ТекущаяДатаСеанса();
Позиция = СтрНайти("abcdef", "cd");
ОткрытьФорму("Форма");
Описание = ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке());
```

Менеджер обработки ошибок доступен через глобальное свойство `ОбработкаОшибок`.
`МенеджерОбработкиОшибок` — имя типа этого свойства, писать его в коде нельзя.

## Источники

Для этой диагностики нет прямого нормативного стандарта 1С: правило покрывает
любой устаревший API платформы, а источником истины служит документация
платформы. Номера ниже относятся к отдельным устаревшим средствам, а не к
правилу целиком.

Связанный публичный контекст:

- [v8std: Работа в разных часовых поясах](https://v8std.ru/std/643/)
- [v8std: Открытие форм](https://v8std.ru/std/404/)
- Описания изменений платформы 1С:Предприятие для устаревших API.
