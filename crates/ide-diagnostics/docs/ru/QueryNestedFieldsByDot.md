# Разыменование ссылочных полей запроса через точку (QueryNestedFieldsByDot)

## Описание диагностики

Диагностика выявляет в тексте запроса разыменование через точку поля, чей тип
в метаданных — составная ссылка, без приведения `ВЫРАЗИТЬ`.

Разыменование такого поля платформа выполняет соединением со всеми таблицами,
входящими в составной тип. Если поле может ссылаться на несколько объектов,
запрос соединяется с таблицей каждого из них, даже когда нужен только один.
`ВЫРАЗИТЬ(... КАК Справочник.Х)` сужает соединение до одной таблицы.

Срабатывает, когда за полем в пути есть ещё один член, а тип поля:

- составной, и хотя бы одна его составляющая — ссылка, например «ссылка на
  номенклатуру или ссылка на склад» и «ссылка на номенклатуру или строка»;
- любая ссылка или любая ссылка одного вида, например стандартный реквизит
  `Регистратор` регистра накопления;
- определяемый тип, основа которого — такой тип.

Не срабатывает:

- на поле одного ссылочного типа: это обычное разыменование, соединение
  получается с одной таблицей;
- на составном типе без ссылок, например «строка или число»;
- на поле, тип которого метаданные не устанавливают: метаданные не подключены,
  поля нет в списке полей таблицы, определяемый тип не найден. Без метаданных
  диагностика не возникает;
- на пути, приведённом `ВЫРАЗИТЬ`: `ВЫРАЗИТЬ(Цены.Объект КАК Справочник.Номенклатура).Код`.
  Условие `ССЫЛКА` приведения не заменяет;
- на `Т.Поле`: конечное имя пути только читается и ничего не разыменовывает;
- на поле, которое модель метаданных перечисляет, не зная, есть ли оно у
  объекта. Так перечислен `Регистратор` регистра сведений, поэтому
  `Регистратор.Дата` регистра сведений не сообщается.

Путь проверяется во всех секциях запроса: в списке выбора, в источниках и
условиях соединений, в `ГДЕ`, `СГРУППИРОВАТЬ ПО`, `ИМЕЮЩИЕ`, `УПОРЯДОЧИТЬ ПО`, в
параметрах виртуальных таблиц и во вложенных запросах. Внутри аргумента
`ВЫРАЗИТЬ` путь проверяется как обычный. После `ВЫРАЗИТЬ` первый член — поле
одной названной таблицы; разыменование дальше по цепочке сообщается, если тип
этого поля — составная ссылка.

## Примеры

Неправильно (`Объект` — ссылка на номенклатуру или на склад):

```bsl
ВЫБРАТЬ
    Цены.Объект.Код КАК Код
ИЗ
    РегистрСведений.ЦеныОбъектов КАК Цены
```

Правильно:

```bsl
ВЫБРАТЬ
    ВЫРАЗИТЬ(Цены.Объект КАК Справочник.Номенклатура).Код КАК Код
ИЗ
    РегистрСведений.ЦеныОбъектов КАК Цены
ГДЕ
    Цены.Объект ССЫЛКА Справочник.Номенклатура
```

## Параметры

| Параметр       | Тип   | По умолчанию | Описание |
|----------------|-------|--------------|----------|
| `minPathDepth` | `int` | `3`          | Минимальное число частей обычного пути от источника запроса, при котором найденное разыменование показывается. Значение по умолчанию `3` показывает `Т.Поле.Реквизит`; большие значения скрывают короткие пути. Двухчастный `Т.Поле` не сообщается ни при каком значении: в нём нет разыменования. |

`minPathDepth` действует только на пути от источника запроса. Разыменования в
параметрах виртуальных таблиц и в цепочках после `ВЫРАЗИТЬ` длины пути от
источника не имеют и показываются при любом значении параметра.

Чтобы полностью отключить диагностику, используйте штатный флаг активации, а не
`minPathDepth`.
