# Поле не найдено в таблице запроса (UnknownFieldInQuery)

## Описание диагностики

Диагностика сообщает о запросе, который обращается к полю, отсутствующему в таблице метаданных.

Чтобы исключить ложные срабатывания, она работает только для таблиц с доказанно полной моделью полей: разрешённые ссылочные объекты, главные таблицы регистров и виртуальные таблицы регистров сведений (`СрезПервых`, `СрезПоследних`), накопления (`Остатки`, `Обороты`, `ОстаткиИОбороты`) и бухгалтерии (`Остатки`, `Обороты`, `ОборотыДтКт`, `ОстаткиИОбороты`, `ДвиженияССубконто`). Для неполных моделей диагностика молчит: это временные таблицы, подзапросы, таблицы регистров расчёта, объекты, разрешённые через расширение, и таблицы регистра бухгалтерии, у которого не найден план счетов (без него неизвестно число полей `Субконто<N>`).

У регистра бухгалтерии с поддержкой корреспонденции имена полей следуют свойству «Балансовый»: небалансовое измерение или ресурс в главной таблице и в `ДвиженияССубконто` называются по сторонам (`<Измерение>Дт`, `<Ресурс>Кт`), а поля `<Ресурс>КорОборот` таблицы `Обороты` есть только у небалансовых ресурсов. Поля, наличие которых зависит от аргументов вызова (`Период`, `ПериодМесяц` и другие разбивки по периоду), считаются существующими.

Путь через ссылочное поле проверяется на каждом хопе: в `Т.Поле.ПодПоле` сначала проверяется `Поле` относительно таблицы, затем `ПодПоле` относительно объекта, на который указывает `Поле` (так же для `Т.Поле.Поле2.ПодПоле` и для табличной части: `Т.Документ.Товары.Колонка`). Сообщается первый доказанно отсутствующий хоп, не более одного замечания на обращение; диапазон - имя именно этого хопа. Набор полей объекта строится так же, как для таблицы в `ИЗ`: реквизиты, стандартные реквизиты (`Ссылка`, `Код`, `Номер`, `Дата`, …), общие реквизиты, табличные части и поля, которые платформа даёт у таблицы запроса (`Представление`, `МоментВремени` у документа).

Диагностика молчит, когда отсутствие не доказано: хоп имеет составной тип, определяемый тип, `ЛюбаяСсылка` или примитивный тип; объект не разрешился (в том числе добавлен расширением); у объекта открытые общие реквизиты; поле объявлено, но может не существовать (условное поле таблицы); путь длиннее 10 хопов. Первый хоп, которого нет в таблице, по-прежнему даёт одно замечание, дальше путь не разбирается.

Две осознанные границы. Проверка молчит за полем, чей тип - значение характеристики (`Характеристика.X`): модель метаданных не отличает его от ссылки на план видов характеристик, поэтому идти за ним нельзя. И проверка идёт дальше первого хопа только там, где тип первого хопа - объявленный реквизит таблицы метаданных; колонка временной таблицы, вложенного запроса или `ВЫРАЗИТЬ` несёт тип, выведенный из выражения (`ВЫРАЗИТЬ(… КАК Т).Поле` типизируется как `Т`, а не как `Поле`), и по такому пути отсутствие не доказывается.

## Примеры

Обращение к несуществующему полю регистра:
```sdbl
ВЫБРАТЬ
	Т.НетТакогоПоля КАК Значение
ИЗ
	РегистрНакопления.Товары КАК Т
```
