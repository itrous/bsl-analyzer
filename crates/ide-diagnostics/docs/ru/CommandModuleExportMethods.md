# Экспортные методы в модулях команд и общих команд (CommandModuleExportMethods)

## Описание диагностики

В модулях команд и общих команд ключевое слово `Экспорт` не формирует
доступный извне программный интерфейс. К таким модулям нельзя обратиться из
другого прикладного кода так же, как к обычному общему модулю, поэтому
экспортный модификатор в обычных методах создает ложное ощущение повторного
использования.

Исключение — метод, зарегистрированный обработчиком оповещения на текущий объект
модуля команды: платформа вызывает такой обработчик по имени и требует `Экспорт`.
Диагностика не отмечает его, если регистрация и её приёмник распознаны.

Неполный набор платформенных фактов о конструкторе `ОписаниеОповещения`
подавляет только выводы об обработчиках: метод, который может быть
зарегистрированным обработчиком, не отмечается, а обычные экспортные методы
по-прежнему проверяются. Если платформенная справка недоступна полностью
(`platform_help = none` или источник справки не найден), правило молчит: без
знаний о конструкторе нельзя отличить обычный экспорт от обработчика.

## Примеры

### Неправильно

```bsl
// Модуль команды
&НаКлиенте
Процедура ОбработкаКоманды(ПараметрКоманды, ПараметрыВыполненияКоманды) Экспорт
    // ...
КонецПроцедуры

// Лишний экспорт -- к этому методу невозможно обратиться извне
&НаСервере
Функция ПолучитьДанные() Экспорт
    Возврат "Данные";
КонецФункции
```

### Правильно

```bsl
// Модуль команды
&НаКлиенте
Процедура ОбработкаКоманды(ПараметрКоманды, ПараметрыВыполненияКоманды)
    // ...
КонецПроцедуры

&НаСервере
Функция ПолучитьДанные()
    Возврат "Данные";
КонецФункции
```
