# Сравнение с текстом имени типа (TypeNameComparedAsText)

## Описание диагностики

Выражение `Строка(ТипЗнч(Значение))` превращает имя типа в текст, а этот текст зависит от языка интерфейса: у одного и того же значения он разный в русском и английском интерфейсе. Если по такому тексту принимается решение, то при смене языка условие молча перестаёт срабатывать: ошибки нет, просто нужная ветка больше не выполняется.

Платформа этого не ловит: сравнение выполняется без ошибки и на языке разработчика даёт ожидаемый результат. Это замечание по стандартам кода, а не ошибка времени выполнения.

Правильно сравнивать типы через `Тип()`: `ТипЗнч(Значение) = Тип("СправочникСсылка.Номенклатура")`. Такое сравнение от языка интерфейса не зависит.

Диагностика срабатывает, когда текст имени типа СРАВНИВАЕТСЯ (`=` или `<>`) СО СТРОКОВЫМ ЛИТЕРАЛОМ, написанным на месте, с любой стороны сравнения.

Что считается текстом имени типа, диагностика решает не по написанию функции, а разбором происхождения значения: оно обязано быть текстом имени типа НА КАЖДОМ ПУТИ, которым исполнение приходит к сравнению. Поэтому отмечается и значение, пришедшее через локальную переменную или через ветвление, если каждое достигшее сравнения присваивание даёт такой текст. Текст сохраняют функции, помеченные таким свойством в данных платформы: `Строка`, `ВРег`, `НРег`, `ТРег`, `СокрЛП`, `СокрЛ`, `СокрП` (и их английские написания) - их можно вкладывать друг в друга.

Замечание ставится на вызов, если текст получен на месте, и на сравнение, если значение пришло через переменную.

### Когда замечания НЕТ

- Текст имени типа только выводится, пишется в журнал, попадает в текст исключения, склеивается, возвращается или сохраняется: от текста ничего не зависит.
- С другой стороны сравнения не литерал, а параметр, переменная или иное выражение: сравнение может оказаться сравнением типа с типом.
- Между получением текста и сравнением значение могло быть перезаписано так, что разбор этого не видит: вызов, который ДОКАЗАННО принимает аргумент по ссылке, либо `Выполнить`. Вызов, про который данные платформы говорят «принимает по значению», замечание не гасит.
- Значение приходит из параметра, из модульной переменной, из переменной цикла или из вызова, который разбор не смог разрешить.

### Чего диагностика пока НЕ ловит

Эти случаи требуют опознания функции по имени, чего диагностика не делает, и будут закрыты отдельными данными платформы:

- `Найти(ИмяТипа, "литерал")`, сравниваемое с числом;
- `СтрНачинаетсяС` и `СтрЗаканчиваетсяНа` с литералом;
- литерал, пришедший как `НСтр("...")` или через переменную;
- обёртки `Лев` и `Прав`, которые берут от текста часть.

## Примеры

Неправильно:

```bsl
Если Строка(ТипЗнч(Значение)) = "СправочникСсылка.Номенклатура" Тогда
    ОбработатьНоменклатуру(Значение);
КонецЕсли;
```

То же через переменную и через сохраняющую текст обёртку (тоже отмечается):

```bsl
Имя = ВРег(Строка(ТипЗнч(Объект)));
Если Имя = "СПРАВОЧНИКССЫЛКА.НОМЕНКЛАТУРА" Тогда
```

Правильно:

```bsl
Если ТипЗнч(Значение) = Тип("СправочникСсылка.Номенклатура") Тогда
    ОбработатьНоменклатуру(Значение);
КонецЕсли;
```

Не отмечается (имя типа только выводится человеку):

```bsl
ВызватьИсключение "Неожиданный тип: " + Строка(ТипЗнч(Значение));
```
