# Минимальные metadata fixtures

Эти XML-шаблоны создают только синтетических владельцев для нативной проверки BSL-модуля. Worker сначала создаёт временную конфигурацию и её `Configuration.xml`, затем добавляет туда ссылки на созданные metadata objects. Исходная конфигурация и данные базы в fixtures не копируются.

В XML допустимы только шаблонные имена и UUID, сгенерированные worker:

- `{{MODULE_NAME}}` и `{{MODULE_UUID}}` — имя и UUID общего модуля;
- `{{CATALOG_NAME}}` и `{{CATALOG_UUID}}` — имя и UUID каталога;
- `{{TYPE_ID_*}}`, `{{VALUE_ID_*}}` — десять разных UUID пяти сгенерированных типов каталога;
- `{{FORM_NAME}}` и `{{FORM_UUID}}` — имя и UUID общей формы.

Все имена проверяются по `^[A-Za-z][A-Za-z0-9_]{0,63}$`; UUID создаёт worker.

Не подставляйте в XML входной BSL, путь, подключение, имя исходного владельца или произвольную строку запроса. Worker записывает исходный текст модуля отдельно в flat module file с BOM UTF-8. Для `snippet` временный общий модуль создаётся из `common_module.xml` со свойствами только серверного модуля; обычный и клиентские контексты в нём выключены.

Формат metadata dump зафиксирован как `2.20`, совместимый с платформой, создавшей этот snapshot. Режим совместимости задаётся и проверяется отдельно в конфигурации временной ИБ; версия XML его не определяет.

`check_templates.py` — проверка только placeholders этих файлов: рендер тестовыми безопасными значениями и разбор через стандартный `xml.etree.ElementTree`. Она не запускает платформу и не доказывает компиляцию BSL.
