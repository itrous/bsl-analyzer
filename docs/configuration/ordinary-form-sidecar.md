# Описание диалога обычной формы (`Ext/Form/Form.json`)

Обычная (неуправляемая) форма хранит диалог в двоичном контейнере `Ext/Form.bin`:
в выгрузке конфигуратора рядом с ним нет ни `Ext/Form.xml`, ни другого читаемого
описания. Поэтому для модуля обычной формы анализатор знает только то, что форма
обычная (`<FormType>Ordinary</FormType>` в её дескрипторе), и не знает ни её
элементов, ни реквизитов, ни того, какие процедуры привязаны к событиям.

Это описание можно положить рядом с модулем отдельным JSON-файлом. Сайдкар может
создать любой инструмент, разбирающий `Form.bin`; анализатор сам `Form.bin` не
читает. Файл необязателен: без него анализатор не знает привязок диалога (см. «Когда
сайдкар не читается»).

## Где лежит

```
Catalogs/Справочник1/Forms/ФормаЭлемента.xml          дескриптор формы
Catalogs/Справочник1/Forms/ФормаЭлемента/Ext/Form.bin  диалог (двоичный)
Catalogs/Справочник1/Forms/ФормаЭлемента/Ext/Form/Module.bsl
Catalogs/Справочник1/Forms/ФормаЭлемента/Ext/Form/Form.json  ← сайдкар
```

Регистр букв в имени файла не важен. Сайдкар читается только для формы без
`Ext/Form.xml`, у которой дескриптор отсутствует или говорит `Ordinary`.
Изменение файла в редакторе обрабатывается как изменение метаданных формы.
Изменение `Ext/Form.bin` тоже инвалидирует метаданные, чтобы повторно проверить
свежесть сайдкара; двоичное содержимое при этом не загружается как текст.

## Что анализатор читает

Читаются только перечисленные ниже поля; все прочие ключи (размеры, привязки
краёв, заголовки, флаги и т.п.) игнорируются, так что производитель может
добавлять свои поля, не нарушая чтение.

| Поле | Тип | Смысл |
|---|---|---|
| `schema` | целое | Версия формата. Нет поля — версия 1. |
| `form.name` | строка | Имя формы; пусто — берётся из пути. Имя и UUID из дескриптора важнее. |
| `form.handlers` | объект «событие → процедура» | События самой формы и её расширения (`ПередОткрытием`, `ПриОткрытии`, `ПередЗаписью`, …). |
| `form.boundHandlers` | массив строк | Все процедуры, которые форма привязывает где-либо, включая действия кнопок командных панелей и меню (у них нет имени элемента). |
| `attributes[].name` | строка | Реквизиты формы. |
| `controls[]` | массив | Элементы диалога, см. ниже. |

Элемент `controls[]`:

| Поле | Тип | Смысл |
|---|---|---|
| `name` | строка | Имя элемента. Безымянный узел (корень диалога) элементом не считается, его дети поднимаются к его родителю. |
| `id` | целое от 0 до 4294967295 | Идентификатор элемента в диалоге; родитель вложенных элементов. Значение вне диапазона делает файл неразбираемым. |
| `kind` | строка | Вид элемента (см. таблицу ниже). |
| `dataPath` | строка | Данные элемента. |
| `handlers` | объект «событие → процедура» | События элемента. Пустое имя процедуры — привязки нет. |
| `columns[].handlers` | объект «событие → процедура» | События колонок табличного поля. Колонки элементами не считаются. |
| `children` | массив | Вложенные элементы (например, на страницах панели). |

Виды элементов и то, как анализатор их классифицирует:

| `kind` | Класс |
|---|---|
| `list` | таблица |
| `input`, `choice`, `checkbox`, `radio`, `listbox`, `textDoc`, `spreadsheet`, `html`, `picture`, `calendar`, `indicator`, `chart`, `graphScheme` | поле |
| `button` | кнопка |
| `label`, `separator` | декорация |
| `commandPanel` | командная панель |
| `panel` | панель со страницами |
| `group` | группа |
| прочие | прочий элемент |

## Версии и совместимость

`schema` — целое число от 1; поля нет — версия 1.

- **Версия 1**: ключа `form.handlers` ещё не было, поэтому для событий самой формы
  берутся имена обработчиков по умолчанию — как для формы без сайдкара. События
  элементов читаются.
- **Версия 2 и выше**: `form.handlers` и `form.boundHandlers` полны. Отсутствующий
  ключ означает «привязок нет», имена по умолчанию не подставляются.

Контракт формата: **новые версии только добавляют поля**. Поля, которые читает
анализатор, сохраняют смысл во всех версиях, поэтому сайдкар любой версии от 1
читается, в том числе версии новее известных анализатору. Производитель, которому
нужно несовместимое изменение описанных здесь полей, обязан писать другой файл
(с другим именем), а не повышать `schema`.

## Когда сайдкар не читается

Во всех случаях ниже форма анализируется так, как будто сайдкара нет, а в журнал
пишется предупреждение `ordinary form sidecar ignored` с путём и причиной:

- файл не читается или это не JSON ожидаемой формы;
- значение `schema` недопустимо (0, отрицательное, дробное, не число);
- **сайдкар устарел**: `Ext/Form.bin` изменён позже, чем `Form.json` (по времени
  изменения файлов). Диалог мог измениться после того, как его описали, и выводы
  по устаревшему описанию были бы ложными. Равное время считается свежим —
  производитель обычно пишет оба файла за один проход; если `Form.bin` нет,
  проверка не выполняется. Содержимое `Form.bin` не сравнивается: если его
  заменили копией, сохранившей более раннее время (распаковка архива, `cp -p`,
  `rsync -t`), устаревший сайдкар не распознаётся. После такой замены сайдкар
  нужно создать заново.

Пока диалог не известен (сайдкара нет или он отвергнут по одной из причин выше),
поиск неиспользуемых локальных методов (`UnusedLocalMethod`) в модуле отключён:
привязки обработчиков к кнопкам диалога неизвестны, и любой метод может оказаться
обработчиком. Если сайдкар есть, но отвергнут, диагностика `OrdinaryFormDialogUnread`
называет причину; отсутствие сайдкара — допустимое состояние и ею не сообщается.

## Что это даёт

С сайдкаром модуль обычной формы проверяется по реальным привязкам и реквизитам формы:

- процедура, привязанная к событию формы, элемента, колонки или кнопки, не
  считается неиспользуемой (`UnusedLocalMethod`, `UnusedParameters`), а процедура,
  которая лишь названа как событие формы, но не привязана, — считается;
- присваивание реквизиту формы не считается неиспользуемой локальной переменной
  (`UnusedLocalVariable`);
- элементы диалога попадают в модель формы (имя, вид, данные, родитель) — так же,
  как элементы управляемой формы из `Form.xml`.
- `ЭлементыФормы.Имя` (`Controls.Name`) разрешается в элемент диалога, а обращение
  к элементу, которого в диалоге нет, даёт `UnresolvedField`. Это ошибка времени
  выполнения («Поле объекта не обнаружено»): обращение связывается поздно, поэтому
  проверка модулей платформы его не видит. Такое обращение не проверяется, если
  модуль может добавить элементы сам: вызывает `ЭлементыФормы.Добавить(...)`,
  передаёт куда-либо `ЭтаФорма` или коллекцию элементов (`ЭлементыФормы`,
  `ЭтаФорма.ЭлементыФормы`, `ЭтаФорма["ЭлементыФормы"]`) — принимающий код может
  добавить элементы, — либо исполняет код из строки (`Выполнить`, `Вычислить`). Элементы, добавленные к форме кодом, получившим её самостоятельно
  (например, через `ПолучитьФорму` в другом модуле), этот анализ не видит.

Свойства и методы самих элементов обычной формы (поле ввода, табличное поле,
кнопка, …) пока не моделируются: тип `ЭлементыФормы.Имя` остаётся открытым.

## Минимальный пример

```json
{
  "schema": 2,
  "form": {
    "name": "ФормаЭлемента",
    "handlers": {"ПриОткрытии": "ПриОткрытии"},
    "boundHandlers": ["ПриОткрытии", "ДействияФормыВыполнить"]
  },
  "attributes": [{"id": 1, "name": "Реквизит1"}],
  "controls": [
    {"kind": "commandPanel", "id": 1, "name": "ДействияФормы"},
    {"kind": "panel", "id": 2, "name": "Панель1", "children": [
      {"kind": "button", "id": 3, "name": "Кнопка1"},
      {"kind": "input", "id": 4, "name": "Поле1", "dataPath": "Реквизит1",
       "handlers": {"ПриИзменении": "Поле1ПриИзменении"}}
    ]},
    {"kind": "generic", "id": 0}
  ]
}
```
