# Поиск ссылок и предварительный план переименования метаданных

API анализа возвращает подтверждённые ссылки BSL, SDBL и поддержанных XML и
строит план правок исходных байтов. Этот слой не записывает файлы. Обычные
`prepare_rename` и `rename` для переменных, параметров и методов сохраняют свой
маршрут; переименование метаданных не выдаётся через обычный WorkspaceEdit.

`Analysis::metadata_target_at` определяет одну цель по позиции в BSL, запросе
или XML. Результат содержит семантический путь, идентичность и исходный диапазон.
Идентичность содержит FileId исходной декларации и UUID владельца/члена. FileId
действует в текущей сессии workspace; это не ключ журнала после перезапуска.
Одинаковые UUID и имена в независимых source roots не объединяются. Заимствование
проверяется по `ObjectBelonging` и `ExtendedConfigurationObject`, включая
вложенные декларации. Совпадение имени не доказывает заимствование.

Для внешнего EPF/ERF используется подготовленный контекст владельца. Собственные
метаданные внешнего объекта относятся к его export root. Ссылки на метаданные
конфигурации требуют явно выбранного и проверенного владельца; legacy default
или неизвестный владелец не подтверждает принадлежность main-конфигурации.

Поиск использует существующие типы получателей, resolver полей и индексы имён.
Каждое вхождение снова проверяется по идентичности цели. Обращения к другому
объекту, поля структур, локальные переменные и пользовательский текст не
становятся ссылками из-за одинакового написания.

Публичные LSP/MCP references используют этот же семантический маршрут. Поиск по
квалифицированному имени отказывает при нескольких независимых идентичностях;
`anchor_files` позволяет выбрать контекст. MCP сохраняет известные вхождения с
`outcome=partial`, причинами неполноты и нижней оценкой числа ссылок. LSP возвращает
непустой набор известных ссылок и фиксирует неполноту предупреждением в журнале.
Если неполный набор пуст, LSP возвращает ошибку с причинами: это не означает
отсутствие ссылок. Полный пустой набор возвращается как пустой ответ. Причинами
неполноты могут быть предел сканирования, необходимое покрытие XML и
неразрешённые динамические ссылки. `include_declaration` управляет XML-декларацией.

Поддержаны следующие обращения:

- имена объектов в менеджерных коллекциях, объявленные реквизиты, табличные части
  и их колонки, значения перечислений и члены регистров, подтверждённые resolver;
- статический строковый ключ индексного обращения к типизированному metadata
  получателю; динамический ключ оставляет причину неполноты;
- таблицы и поля статических запросов, связанные с таблицей и alias при SDBL
  lowering. Источник строки должен быть подтверждённым конструктором
  `Query`/`Запрос` или присваиванием его `Text`/`Текст`. Строка для отображения
  пользователю не становится запросом по содержимому;
- точные диапазоны BSL-строки запроса: Unicode, CRLF и удвоенные кавычки
  отображаются существующим mapper. Непредставимый единым диапазоном токен
  блокирует полный результат;
- XML `Name` деклараций, списки объектов Configuration, текущие типы конфигурации,
  типизированные `MDObjectRef`, managed-form `DataPath`, проверенные имена команд
  CommandInterface и состав ExchangePlan;
- Local-запросы СКД и вложенные поля их выходных ссылочных значений. `field`
  связывается с выходным полем запроса; `dataPath` и подпись сохраняются;
- простой путь вычисляемого поля СКД: `Partner.Caption` связывается через
  `DataSetFieldField.dataPath` → `field` → уникальный ссылочный SELECT output.
  Проверяются тип получателя и UUID реквизита; локальное имя вычисляемого поля
  и подпись остаются прежними. Поддержан один Local DataSetQuery с прямыми
  alias-полями. Общие формулы, функции, параметры, scalar/union outputs,
  неоднозначные alias и неизвестные пути запрещают применение;
- ConfigDumpInfo hierarchical 2.20: имя привязывается к UUID декларации или
  контейнера в том же снимке корня. `id`, `configVersion` и suffix не вычисляются
  и не переписываются;
- UUID-owned GeneratedType name для подтверждённых native категорий Catalog и
  InformationRegister. Category/prefix должны совпасть с исходным владельцем;
  TypeId/ValueId и прочие байты сохраняются.

Managed-формы используют подготовленные источники формы и UUID-проверенную
композицию base+CFE. Нельзя заменить неизвестное содержимое расширения только
базовой формой. Локальная колонка ValueTable сама не является метаданными;
вложенная ссылка подтверждается только по объявленному ссылочному типу колонки.

Переименование поля запроса сохраняет его прежнее неявное выходное имя через
явный `AS`, чтобы обращения BSL к результату `Select`/`Unload` не разрывались.
Wildcard целевой таблицы оставляет явную неполноту. При переименовании объекта
неявный alias физической двухсегментной таблицы сохраняется через `AS OldName`;
существующие явные alias и обращения к чужому объекту сохраняются.

`prepare_metadata_rename_plan` принимает неизменяемый снимок корней, файлов,
каталогов и открытых документов. План содержит исходные/новые байты файлов,
точные диапазоны, прежние байты и операции переименования descriptor/container
при смене имени объекта. Read set включает неизменённые файлы, состав каталогов,
роли и привязки корней, raw SHA-256, версии и отдельный SHA-256 текста редактора.
Symlink, dirty document, несовпадение resident/raw source, readonly root,
коллизии имён, отсутствующий input и неподдержанная поверхность блокируют apply.

XML reader сохраняет UUID, BOM, encoding, CRLF и несвязанные байты без повторной
сериализации документа. Его отдельные byte-level тесты поддерживают UTF-16;
это не расширяет runtime loader, который публикует только UTF-8. Неподдержанная
runtime-кодировка не получает подтверждённый resident input.

Поддержка XML ограничена перечисленными контрактами. Неизвестные свойства,
namespace, категории GeneratedType, структуры и выражения оставляют явную
неполноту; они не получают разрешение на запись по совпадению текста. В
CommandInterface дочерние sections/Command и в ExchangePlanContent Item/Metadata
должны принадлежать namespace поддержанного формата. ExchangePlan Item содержит
ровно один Metadata и не более одного scalar AutoRecord (Allow/Deny). В
CommandInterface Command допускается только unqualified name и известные
scalar CommandGroup/Placement. Неизвестные attributes/children, дубликаты и
вложенная форма scalar значения запрещают применение; первый подходящий узел
не подменяет проверку всего элемента. Неподдержанное бинарное
содержимое ordinary-форм не объявлено поддержанным форматом перезаписи.
Положительный reader ordinary-форм относится к отдельному контракту inspection.
Обычный readonly preview сохраняет
`XmlCoverageRequired` и `SnapshotBindingRequired` и не разрешает применение.
Положительный pure plan для поддержанного полного снимка не заменяет проверку
серверного применения и нового клиента в принятой эксклюзивной сессии.
Серверный кандидат использует отдельный
[LSP-протокол preview/commit/abort](METADATA_RENAME_PROTOCOL.md), полный снимок и
журнал восстановления. Общая публикация моделей нескольким клиентам и actual
VS Code Extension Host проверяются отдельно. Собственный lock не блокирует
сторонних writers.


## Проверяемые поверхности

| Поверхность | Положительный контракт | Отказ при неопределённости |
| --- | --- | --- |
| XML declarations/types | UUID, вложенные декларации, известные typed references и raw spans | неизвестное свойство, namespace, форма значения или привязка |
| Managed form DataPath | prepared base+CFE attributes, nested paths, typed ValueTable columns | недоказанное наследование, отсутствующий/неоднозначный тип |
| СКД | Local query metadata, typed output subfields, простой calculated-field path | dynamic/general expression, неподдержанный набор/тип, ambiguous alias |
| CommandInterface | metadata owner в CommandsPlacement/CommandsOrder, пользовательские подписи не заменяются | неизвестная секция, неверный namespace или неподтверждённое имя |
| ExchangePlanContent | metadata owner с сохранением AutoRecord, комментариев и другой сущности | неизвестный формат/namespace или путь |
| Строковые ключи BSL | literal index key типизированного metadata receiver | dynamic key, unknown receiver; обычные строки не повышаются до ссылок |

Исходные проверки находятся в `bsl-metadata::rename_xml` и
`ide::metadata_rename`: byte/encoding controls, UUID и другой owner, prepared
form bindings, SDBL output contracts, namespace injection и реальные планы
CommandInterface/ExchangePlanContent. Эти unit/plan проверки не заменяют
проверки native import/export и LSP/MCP/VS Code на текущем кандидате.
