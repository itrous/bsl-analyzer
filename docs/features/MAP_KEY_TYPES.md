# Типы значений Соответствия по строковому ключу

Платформа описывает `Соответствие.Получить` без типа результата, поэтому без этой возможности
результат любого чтения — `Неопределено`. Анализатор уточняет тип результата
`Соответствие.Получить("ключ")`, когда ключ и тип его значения известны из кода тела или из
документирующего комментария.

```bsl
Процедура Пример()
	Данные = Новый Соответствие;
	Данные.Вставить("сумма", 1);
	Данные.Вставить("готово", Истина);
	Сумма = Данные.Получить("сумма");   // Число
	Готово = Данные.Получить("готово"); // Булево
КонецПроцедуры
```

## Что меняется

- Тип результата вызова `Получить`: его показывает hover переменной, которой присвоен результат
  (`**Тип:** Число`), и по нему работают существующие проверки аргументов и членов. Если ключ
  доказан, передача `Данные.Получить("сумма")` в параметр типа `Число` больше не даёт
  `TypeMismatch*`.
- Тип самой переменной-Соответствия не меняется: hover `Данные` — `Соответствие`, перечень ключей
  не показывается.
- Hover слова `Получить` остаётся платформенным: подпись метода строится из платформенных данных,
  а не из типа конкретного вызова.
- Новых диагностик нет.

## Когда уточнение работает

- Включён профиль `mapKeyTypes` (по умолчанию включён, см. ниже).
- Платформенные данные находят метод `Соответствие.Получить`/`Map.Get`. Встроенных фактов
  достаточно; номер версии платформы (`target_platform_version`, `min_platform_version`) сам по
  себе уточнение не включает и не выключает.
- Приёмник — именно `Соответствие` (не объединение типов, не `ФиксированноеСоответствие`).
- Вызов имеет ровно один аргумент — строковый литерал: `Получить("сумма")`. Ключ-переменная,
  вызов без аргументов или с двумя аргументами не уточняются.
- Индексное чтение `Данные["сумма"]` не уточняется.

## Источник 1: Соответствие, построенное в теле

Корень — локальная переменная метода, которой ровно один раз присвоен пустой конструктор:
`Новый Соответствие`, `Новый Соответствие()` или `Новый Map`. Параметр, переменная модуля,
свойство формы, глобальное имя и конструктор с аргументами корнем не бывают.

Записи — отдельные операторы `Данные.Вставить("ключ", значение)` (`Insert`) со строковым
литералом в качестве ключа. Значение должно быть литералом: строка, число, `Истина`/`Ложь`, дата,
`NULL`, `Неопределено`. Для отрицательного числа (`-1`), переменной, вызова, конструктора и
`Вставить("ключ")` без значения тип ключа неизвестен: такой ключ не уточняется, остальные ключи
того же Соответствия уточняются как обычно.

Тип результата — объединение типов **всех** записей этого ключа в теле, в том числе записей после
чтения: перезапись другим типом расширяет результат, а не заменяет его.

### Наличие ключа

Если наличие ключа доказано, результат — тип значения (`Число`). Иначе к нему добавляется
`Неопределено` (`Число | Неопределено`). Наличие доказано, когда:

- запись того же ключа стоит в том же списке операторов, что и конструктор, раньше чтения;
- у Соответствия нет ни одной условной записи — записи внутри `Если`/`ИначеЕсли`/`Иначе`,
  `#Если`, циклов `Пока`/`Для`/`Для Каждого`, `Попытка`/`Исключение`. Даже условная запись
  другого ключа снимает доказательство наличия.

Чтение до записи (в том числе в условии `Если`, тело которого делает запись) наличие не
доказывает. Конструктор внутри цикла создаёт новое Соответствие на каждой итерации, поэтому
записи прошлых итераций до чтения не доходят.

### Сравнение ключей

Ключи сравниваются без учёта регистра: `Вставить("Сумма", 1)` доказывает наличие для
`Получить("сумма")`, а записи `"Сумма"` и `"сумма"` относятся к одному ключу. Остальные символы
значимы и не нормализуются: пробелы (в том числе ведущие и замыкающие), дефисы, кавычки —
`"а-б"`, `"а б"` и `"а - б"` — три разных ключа.

### Что отключает уточнение

Любое из событий ниже возвращает прежний тип (`Неопределено` на встроенных фактах) для всех
чтений этого Соответствия, даже если событие стоит после чтения:

- второе присваивание переменной, в том числе как переменной цикла `Для`/`Для Каждого`;
- упоминание переменной вне операторов, следующих за конструктором в его списке (например,
  конструктор в ветке `Если`, а чтение после `КонецЕсли`; чтение до конструктора);
- псевдоним: `Копия = Данные`;
- выход Соответствия за пределы метода: аргумент любого вызова (в том числе параметр `Знач`),
  аргумент `Новый`, элемент массива, `Возврат Данные`, `ВызватьИсключение`, операнды
  `ДобавитьОбработчик`/`УдалитьОбработчик`;
- неизвестная мутация: `Удалить`, `Очистить`, любой другой метод кроме `Получить` и
  `Количество`; `Вставить` не в виде отдельного оператора, с ключом-не-литералом или с лишним
  аргументом; запись по индексу `Данные["к"] = …` и запись свойства `Данные.Х = …`; вызов метода
  на выражении, которое может вычислиться в это Соответствие (`?(Условие, Данные, Другое).Вставить(…)`);
- `Выполнить`, `Вычислить` (даже если имя переопределено своим методом) или `Перейти` в теле —
  уточнение отключается для всех Соответствий метода.

Не отключают уточнение: `Получить`, `Количество`, чтение по индексу и свойству, передача или
возврат **результата** `Получить`, вызов метода на результате (`Данные.Получить("к").Метод()`).

## Источник 2: документирующий комментарий

Ключи параметра или возвращаемого значения описываются пунктами с ключом в двойных кавычках
прямо под слотом `Соответствие` (`Map`):

```bsl
// Параметры:
//   Данные - Соответствие:
//     * "сумма" - Число - сумма документа.
//     * "дата-документа" - Дата
//     * "имя клиента" - Строка, Неопределено
//
// Возвращаемое значение:
//   Соответствие:
//     * "сумма" - Число
//     * "а - б" - Булево
//     * "а""б" - Строка
```

Правила разбора:

- Голова слота — ровно `Соответствие` или `Map` (регистр не важен), двоеточие необязательно.
  Форма `Соответствие из КлючИЗначение` (хвост `из …`/`of …` в имени или в начале описания) и её
  пункты `* Ключ - Тип` / `* Значение - Тип` ключами не являются.
- Ключ — строковый литерал BSL: всё между открывающей кавычкой и первой одиночной закрывающей,
  `""` внутри означает одну кавычку. Пробелы, дефисы и ` - ` внутри кавычек — часть ключа.
- После закрывающей кавычки — пробелы, `-`, хотя бы один пробел, затем типы через запятую и
  необязательное описание после ` - `, как в строке параметра. Незакрытая кавычка,
  `"а"-Число` (нет пробела после дефиса) и пункт без кавычек (`* сумма - Число`) ключа не дают.
- Пункт однострочный: продолжения и вложенные пункты под ним не читаются.
- Пункты, ключи которых совпадают без учёта регистра, — один ключ: имя берётся из первого
  написания, тип — объединение типов всех пунктов.

Документированный ключ наличия не доказывает: результат всегда `T | Неопределено`
(`Произвольный` поглощает объединение). Ключа нет среди пунктов или тип пункта неизвестен
(`НеТакогоТипа`, нечитаемая альтернатива вроде `Соответствие из Строка`) — платформенный
результат `Получить` (`Неопределено` на встроенных фактах).

Ключи доходят до вызывающего через тип сигнатуры: `Д = Ф(); Д.Получить("сумма")` и
`Ф().Получить("сумма")`. Внутри метода уточняется чтение документированного параметра.
Уточнение не работает, если:

- приёмник — переменная, которая в теле изменена или выпущена (те же события, что выше, включая
  запись `Вставить`), параметр, которому что-то присвоено, или локальная с двумя и более
  присваиваниями; в теле есть `Выполнить`, `Вычислить` или `Перейти`;
- слот — объединение (`Неопределено, Соответствие:`) и приёмник не сужен до `Соответствие`;
- запись стоит под `Массив из`, в поле Структуры, во вложенном пункте или приходит через `см.`
  на чужой метод.

Параметр с пунктами-ключами при включённом профиле входит в тело метода как `Соответствие`,
поэтому неуточнённое чтение такого параметра (ключ не из пунктов, параметр изменён или выпущен,
в теле `Выполнить`, `Вычислить` или `Перейти`) даёт платформенный результат
`Неопределено`. При выключенном профиле такой параметр в тело не подаётся, и тип его чтения
неизвестен, как и раньше.

Обычное и документированное Соответствие совместимы в обе стороны: `Проц(Новый Соответствие)`
при документированном параметре и передача результата документированной функции в параметр
`Соответствие` находок `TypeMismatch*` не дают.

## Пределы

- **Размер:** 64 различных ключа (после сравнения без учёта регистра) на одно Соответствие — и
  для записей в теле, и для пунктов документации. Больше — Соответствие ответов не даёт вовсе
  (прежний тип для любого ключа), первые 64 ключа не сохраняются.
- **Глубина:** 1. Значение-Соответствие внутри ключа не отслеживается.

## Профиль `mapKeyTypes`

Возможность включена по умолчанию и выключается в `bsl-analyzer.toml`:

```toml
[features]
mapKeyTypes = false   # допустимо и map_key_types = false
```

Выключенный профиль выключает оба источника: тип `Получить` и находки возвращаются к прежним,
документированные пункты с ключами не меняют тип параметров и возвращаемых значений. Описание
секции — в [`docs/configuration/PROJECT_CONFIGURATION.md`](../configuration/PROJECT_CONFIGURATION.md#features).

## Что не меняется

- Структура: её ключи, поля и проверки работают как раньше.
- Индексное чтение `Данные["ключ"]`.
- `ФиксированноеСоответствие` не уточняется.
