# BA-023: платформенная проверка полного BSL-модуля

Статус: реализация и приёмка завершены; результаты и границы проверки приведены ниже. [Настройка профиля и контракт MCP](../mcp/TOOLS_AND_EXTENSION.md).

## Принятое решение

Выбран вариант «Одноразовая копия». Нативная проверка выполняется в изолированной временной ИБ, созданной по конфигурации выбранного `connection`; исходная ИБ используется только для чтения. Копия воспроизводит точную сборку платформы, режим совместимости, применённую конфигурацию и действующий состав расширений. Если соответствие не подтверждено, результат нельзя объявлять проверкой для этой ИБ. Для приёмки использованы demo (D), минимальная база в режиме `Version8_2_16` (L) и минимальная база с современной совместимостью (M).

Следствие: вариант с запуском компилятора физически в исходной ИБ для новых текстов не выбран. Копирование и прототипная native/MCP-проверка выполнены на D/L/M; общие gates завершены. Внешние EPF/ERF рассматривались только как сравнительный носитель и не входят в BA-023.

## Причина дефекта

BA-023 воспроизводился на версиях 0.2.77–0.2.85: полный модуль с объявлениями и директивами получал ложную ошибку «Неопознанный оператор» или «Ожидается ключевое слово КонецЕсли» из HTTP-сервиса, хотя короткий набор операторов проверялся корректно. Код исследован на `a89a157c2a5816b18daf5cd231f744a85743374b`. Минимальный корректный модуль управляемой формы:

```bsl
&НаКлиенте
Процедура Тест(Команда)
КонецПроцедуры
&НаСервереБезКонтекста
Функция Тест2(Знач А) Экспорт
    Возврат А;
КонецФункции
```

Цепочка проверки до исправления (исследованный `a89a157c`):

1. [ExecuteParams и execute](../../crates/mcp-server/src/lib.rs) принимают `action`, `code`, `connection`, `max_output_tokens`; тип модуля и его владелец отсутствуют. Ветка `check` передаёт текст в `tools::execution::check_syntax`.
2. [check_syntax](../../crates/mcp-server/src/tools/execution.rs) выбирает live-подключение и отправляет `CheckSyntaxRequest { code }`. Ограничение `allow_execute` относится к `run`/`eval`, проверку оно не блокирует.
3. [onec-client](../../crates/onec-client/src/lib.rs) вызывает `/check-syntax`; ответ содержит только `valid` и необязательный текст `error`.
4. [ПроверкаСинтаксисаPOST](../../extension/src/HTTPServices/BSLAnalyzerService/Ext/Module.bsl), строки 384–409, добавляет перед текстом строку `Если Ложь Тогда`, после него — `КонецЕсли;`, затем на строке **401** вызывает `Выполнить(ТекстДляПроверки)`. Исключение возвращается через `ОписаниеОшибки()`; MCP отображает его как текст.

Это компиляция набора операторов в серверном контексте HTTP-обработчика. Самостоятельные `Процедура`/`Функция` и директивы модуля здесь неприменимы. Первая исходная строка становится второй строкой сгенерированного текста; сейчас смещение не исправляется. Строка 401 — место вызова в сервисе, а не позиция ошибки пользователя. Версия HTTP-компонента не сообщает сборку платформы и режим совместимости.

## Сравнение вариантов

Номера позиций ниже относятся к исходному BSL; привилегированный режим BSL не заменяет права на конфигурацию или доступ к компилятору.

| Вариант | Контексты и директивы | Позиции | Затрагиваемая ИБ и права | Оценка |
|---|---|---|---|---|
| Текущий `Выполнить()` | Серверный набор операторов; объявления модуля и клиентские директивы не проверяются | Сейчас +1 строка; нужна карта обёртки | Исходная ИБ, права HTTP-сеанса; повышение привилегий дефект не исправит | Сохранять как проверку полного модуля нельзя |
| Временная EPF/ERF, модуль объекта, создание в Предприятии | Сравнительный вариант носителя; серверное создание не подтверждает клиентские части формы и не заменяет общий/менеджерский модуль | При неизменённом тексте смещение 0 | ИБ загрузки; права на внешние объекты и ограничения безопасного режима. Возможно исполнение инициализации | Вне BA-023 |
| Модуль формы, создание/открытие формы | Контекст формы с реквизитами; управляемая форма требует клиентского и серверного проходов, обычная — обычного приложения | 0 для текста модуля, отдельно сопоставляется владелец формы | ИБ открытия и клиент; возможны события формы. Привилегированный режим не даёт HTTP-сеансу клиентский компилятор | Открытие формы не подходит для проверки без исполнения |
| Разбор и проверка процедур отдельно | Можно разбирать объявления анализатором, но теряются модульные переменные, связи, дубликаты, препроцессор и контексты; `Выполнить` всё равно не принимает объявления | Нужна карта срезов и обёрток | Статический разбор не требует ИБ; нативные фрагменты используют выбранную ИБ | Только предварительная диагностика, не замена платформенной проверки |
| Конфигуратор `/CheckModules` в исходной ИБ | Нативные проходы по выбранным режимам для уже загруженной конфигурации; `/CheckConfig` даёт дополнительные режимы/проверки | Текст не сдвигается; формат нативных координат требует подтверждения | Для произвольного нового текста пришлось бы менять исходную конфигурацию; нужны права Конфигуратора и лицензия, не привилегированный BSL | Нарушает принятое ограничение |
| **Конфигуратор в одноразовой копии** | Сохраняет настоящий тип/владельца модуля и метаданные. Проверяются применимые клиентские, серверные и внешние контексты; ветви препроцессора — отдельными проходами | Преобразование текста: смещение 0 для модуля, карта для обёрток; нативные позиции подтверждены для проверенных вариантов текста | Исходная ИБ только читается; изменения и удаление происходят в копии. Права чтения/выгрузки источника, права и лицензия worker | **Выбран и проверен на D/L/M** |
| `ibcmd config check` | В локальной справке 8.3.27.1989 не установлена эквивалентность проверке BSL во всех режимах; выбор проходов не указан | Формат BSL-координат не подтверждён | ИБ, указанная команде; служебная авторизация, не привилегированный BSL | Допустим для подготовки копии после проверки возможностей; не считать заменой `/CheckModules` |

Документированные команды проверки Конфигуратора и переключатели режимов приведены в [руководстве администратора](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.22_Administrator_Guide/Appendix_7._The_parameters_of_the_command_line_to_launch_1C_Enterprise/7.4._Running_Designer_in_batch_mode/7.4.5._Checking_configurations_and_extensions/). Команды выгрузки/загрузки внешних файлов [документированы отдельно](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.27_Administrator_Guide/Appendix_7._Startup_command-line_options_of_1C_Enterprise/7.4._Running_Designer_in_batch_mode/7.4.8._External_reports_and_data_processors/?language=de); это не подтверждение проверки синтаксиса EPF/ERF, которые не входят в BA-023. Универсальную команду `CheckExternalDataProcessorOrReport` проект не предполагает.

## Выбранный подход и входные данные

Добавить к `execute(action="check")` два режима: `input_kind="snippet"` и `input_kind="module"`. Отсутствующий `input_kind` сохраняет режим фрагмента для прежних клиентов. Обнаруженное объявление в таком запросе возвращает `context_required` с требованием указать режим и тип модуля, а не ложную синтаксическую ошибку. Автоматически угадывать тип по директивам нельзя.

Для модуля обязательны `module_type` и описание контекста:

| `module_type` | Необходимые метаданные и проходы |
|---|---|
| `object` | Вид владельца: объект конфигурации; реквизиты, табличные части, предопределённые методы. Проверять режимы, где этот модуль существует. Внешние EPF/ERF не входят в BA-023 |
| `managed_form` | Владелец и форма, её реквизиты и параметры. Минимум тонкий клиент и сервер; веб-клиент и другие режимы — если форма предназначена для них |
| `ordinary_form` | Владелец и обычная форма; обычное приложение, с учётом файлового/серверного варианта |
| `common` | Имя и свойства настоящего общего модуля: клиент/сервер/внешнее соединение, глобальность, вызов сервера, привилегированность. Отдельные применимые проходы |
| `manager` | Точный объект-владелец и его вид; режимы доступности менеджера. Не подменять модулем объекта обработки |

Для существующего модуля `owner` задаёт полный путь метаданных, `origin` — основную конфигурацию или конкретное расширение. Worker заменяет весь текст **в соответствующем модуле копии**, сохраняя остальные свойства. Заимствованный модуль расширения проверяется вместе с основной конфигурацией и действующими расширениями, включая необходимые условия применимости и область данных; изолированное CFE не эквивалентно этому контексту. Неоднозначный владелец — `context_required`.

Внешние EPF/ERF не входят в BA-023; их возможный контекст не следует подменять встроенным объектом. Самодостаточное минимальное воспроизведение допускает явно выбранный синтетический контекст управляемой формы; ответ указывает его и не обещает проверить реквизиты реальной формы.

Директивы `&НаКлиенте`, `&НаСервере`, `&НаСервереБезКонтекста` и их сочетания должны трактоваться компилятором выбранного типа модуля, а не удаляться перед проверкой. [Стандарт 439](https://its.1c.ru/db/v8std#content:439) описывает рекомендуемые области применения директив; рекомендации стандарта не заменяют грамматику конкретной платформы. [Настройки нативной проверки](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_8.3.24_Developer_Guide/Chapter_36._Service_features/36.2._Setting_Designer_parameters/36.2.3._Modules/) подтверждают, что отсутствующий в выбранном режиме модуль может быть пропущен. Поэтому пустой журнал одного серверного прохода не доказывает корректность клиентского модуля.

## Выполнение и ответ

`connection` выбирает серверный профиль компилятора, связанный с той же ИБ, что и HTTP-клиент. Одного HTTP URL недостаточно для запуска Конфигуратора. Это новый backend MCP, а не попытка запускать Конфигуратор из HTTP-сеанса. Если профиль отсутствует, вернуть `unsupported`; статический анализатор не выдавать за нативный результат.

1. Получать точную сборку платформы, фактический режим совместимости и снимок **применённой конфигурации БД**, а не несохранённых изменений основной конфигурации Конфигуратора. Сохранять отпечатки, свойства/порядок действующих расширений, режимы запуска и условия их применимости. Для каждого выбранного источника копия сохраняет именно его режим; если источник использует `Version8_2_16`, сохранять это значение. Не повышать совместимость ради временного объекта. Конкретные базы BP20/BP30 не обязательны.
2. Создать собственную изолированную ИБ без бизнес-данных, загрузить снимок и заменить нужный текст. Не запускать Предприятие, модуль инициализации, обработчики запуска или события форм. Эквивалентность файловой копии серверному источнику по выбранным режимам должна быть доказана; иначе нужен соответствующий вариант временной ИБ или `unsupported`.
3. Выполнить нативные проходы `/CheckModules` с обязательными применимыми флагами. Для режимов, которые доступны только через `/CheckConfig`, использовать его с синтаксическими флагами. Проверить охват основной конфигурации и расширений; `-Extension`/`-AllExtensions` сами по себе не доказывают, что целевой модуль вошёл в каждый проход.
4. Разделить ошибки исходного текста, зависимостей/окружения и инфраструктуры. Нативная проверка может выдавать ошибки других модулей: не приписывать их переданному тексту и не удалять простым вычитанием старого журнала. Ошибка окружения, не позволяющая проверить модуль, даёт `error`, а не `valid=true`.
5. Повторно сверить состояние источника: изменение снимка/расширений во время задания означает устаревший результат и повтор либо явный `error`. Удалить принадлежащие заданию ИБ, файлы и процессы при успехе, ошибке, отмене и по таймауту. После аварии очистку завершает сборщик по журналу владения; ошибка очистки отражается отдельно.

Для фрагмента создать **в конфигурации копии** временный серверный общий модуль: строка `Процедура ПроверкаФрагмента()`, неизменённый вход, строка `КонецПроцедуры`. Проверить этот модуль `/CheckModules -Server`, не вызывая процедуру и не запуская Предприятие. Этот compile-only путь прошёл нативные и MCP snippet smoke-пары; Linux/N2 и локальный Windows GNU CI завершены. Сохранить серверные глобальные имена и метаданные выбранной ИБ; доступ к локальным переменным HTTP-обработчика не обещать. Нельзя считать ложное условие в текущей текстовой обёртке гарантией отсутствия исполнения произвольного входа; негативный тест должен пытаться закрыть добавленный блок. Совместимость привычных коротких фрагментов подтверждается отдельными тестами.

Расширить результат до `status = valid | invalid | context_required | unsupported | error`, `valid = true | false | null`. Только `invalid` означает полученную ошибку компиляции исходного модуля. Передавать тип/владельца, фактически проверенные контексты, сборку платформы, совместимость и отпечаток снимка; `issues` содержит сообщение и координаты. MCP JSON Schema, описание tool и публичный контракт обновлены; прежний HTTP endpoint не используется для `check`. Ответ содержит текст и структурированные данные. Для проверки фрагментов также требуется профиль `native_check`; одного прежнего `--onec-url` недостаточно.

Строка и колонка — **1-based в переданном тексте**. Полный модуль записывать без добавления строк: смещение 0. Для процедуры-обёртки фрагмента вычесть точное число строк префикса; ошибки служебного префикса/суффикса классифицировать как ошибку генерации. Не обрезать текст и не менять отступы. Единицы нативной колонки проверить на табуляции, кириллице и символах вне BMP; публичную колонку нормализовать в UTF-16. LF/CRLF и BOM учитывать в карте преобразований. Если компилятор не предоставил надёжную позицию, не подставлять колонку 1: вернуть `error` с причиной `position_unavailable` и безопасным диагностическим текстом.

Привилегированный режим не включать автоматически ([стандарт 485](https://its.1c.ru/db/v8std#content:485)). Использовать отдельные минимальные права чтения/выгрузки источника и создания/удаления копий. Пароли, строки соединения, приватные URL и сырые аргументы процесса не включать в ответы, журналы и артефакты. Способ передачи авторизации без раскрытия — проверка осуществимости backend; временные источники и журналы доступны только worker. Ограничить время, размер текста/вывода и число одновременных заданий; обрезанный вывод не должен превращать ошибку в успех.

## Ограничения и оценка архитектуры

Проверка компиляции не подтверждает существование привязанных обработчиков событий формы, корректность их сигнатур, исполнение бизнес-логики, права пользователя, содержимое данных, динамические имена метаданных и `Выполнить`/`Вычислить` внутри модуля. Проверка обработчиков требует отдельного `/CheckConfig -HandlersExistence` и полноценной схемы формы; она не входит в BA-023. Неактивные ветви препроцессора в непроверенных режимах остаются непокрытыми. Модули без доступного исходного текста также непокрыты.

Выбранный вариант устраняет неверный контекст компиляции и сохраняет исходную ИБ. Цена — worker с нужными сборками платформы/лицензиями и более высокая задержка проверки. Допустим повторно используемый неизменяемый снимок метаданных по отпечатку; изменяемая ИБ и текст каждого задания изолированы. Содержимое клиентской конфигурации не передавать во внешние сервисы.

**Текущий статус:** одноразовые копии D/L/M, чтение применённой конфигурации и состава расширений, нативные пары пяти типов и координатные проверки пройдены в заявленных smoke-наборах. Общая приёмка и итоговая очистка завершены. Поддержка EPF/ERF не входит в BA-023; будущие проверки внешнего точного контекста не являются gate этого изменения.

## Проверки приёмки

На Windows GNU пройдены 250 команд существующего задания `windows-mcp` и 3 дополнительные проверки BA-023, затем собран актуальный бинарник. Нативный Designer на Windows и MSVC этим результатом не подтверждаются. Временные ресурсы приёмки удалены; исходная demo использовалась только для чтения.

| Требование / риск | Проверка и ожидаемый результат |
|---|---|
| Полный модуль и директивы | Минимальный пример пользователя как `managed_form`; объявления процедур/функций, `Экспорт`, переменные модуля, вложенные `Если`, клиентские/серверные директивы и препроцессор. Нативный эталон и MCP дают одинаковый результат по каждому применимому проходу |
| Тип и метаданные | Положительные модули объекта, обеих форм, общего и менеджера с реальным владельцем; ссылки на объекты основной конфигурации и действующего расширения. Отсутствующий/неоднозначный владелец даёт `context_required`. Внешние EPF/ERF не входят в эту матрицу |
| Реальные ошибки | Нет `КонецПроцедуры`/`КонецФункции`/`КонецЕсли`, ошибочный оператор, дубликат объявления, недопустимая директива для выбранного типа. Проверить нативный эталон: `invalid` с его ошибкой в исходном тексте, без ссылки на HTTP401 как пользовательскую позицию |
| Координаты | Ошибки в первой/последней строке и середине процедуры; пустые строки, LF/CRLF, BOM, табы, кириллица, вне-BMP. Строка/колонка совпадают с отмеченной позицией, служебные строки не попадают в `issues` исходника |
| Совместимость выбранных источников | Сохранять фактический режим каждого выбранного источника и сверять его с копией и сборкой worker. В D/L/M проверены режимы `Version8_3_27` и `Version8_2_16`; BP20/BP30 не являются обязательными источниками или gates приёмки |
| Регрессия фрагментов и API | Короткие корректные/некорректные операторы без объявлений, старый запрос без `input_kind`, пустой код, неверное имя подключения, усечение вывода. Синтаксический итог не меняется от бюджета; новый контракт и старый текст согласованы |
| Охват и ошибки окружения | Ошибка только в клиентской ветви, только в серверной, во внешнем соединении и обычной форме; отсутствие нужного прохода, несовпадение сборки, устаревший снимок, потерянное расширение, ошибка зависимости. Нельзя получить ложный `valid=true` |
| Данные, исполнение, надёжность | Контрольные маркеры в инициализации/событиях и вход с закрытием обёртки не исполняются. Исходная конфигурация/данные неизменны. Успех, ошибка, параллельные задания, таймаут, отмена и авария оставляют только журнал очистки, без чужих удалений и утечки секретов |

Критерий готовности: для каждого заявленного контекста MCP совпадает с проверкой тем же нативным компилятором в эквивалентном контексте, ошибки имеют точные исходные координаты, фрагменты продолжают проверяться, исходная ИБ не меняется и временные ресурсы удалены. Этот критерий подтверждён описанной приёмкой; другие сборки платформы требуют собственной калибровки контекстов и координат.
